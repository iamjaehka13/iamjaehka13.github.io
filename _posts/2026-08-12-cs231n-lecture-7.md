## **0. 이 글의 목표**

[Lecture 6의 CNN architecture와 학습 전략](/posts/cs231n-lecture-6/)까지는 대체로 고정된 크기의 입력을 한 번에 받아 고정된 크기의 출력을 만드는 network를 다뤘다. 그러나 video, 문장, sensor stream처럼 순서와 길이가 있는 데이터에서는 현재 입력만으로 답을 정할 수 없는 경우가 많다. 같은 `1`을 보더라도 직전 값이 `0`인지 `1`인지에 따라 "연속된 두 개의 1"인지가 달라진다.

Sequence model에는 다음 질문이 생긴다.

- 길이가 달라지는 입력과 출력을 하나의 parameter 집합으로 어떻게 처리할 것인가?
- 과거의 어떤 정보를 hidden state에 남길 것인가?
- 같은 weight가 여러 시점에 쓰일 때 gradient를 어떻게 계산할 것인가?
- 긴 sequence에서 memory와 gradient가 왜 사라지거나 폭발하는가?
- image feature와 language sequence를 하나의 model에서 어떻게 연결할 것인가?

핵심은 **과거 전체를 보관하는 것이 아니라, 다음 계산에 필요한 정보를 고정 크기의 state로 압축하고 같은 update rule을 시간축 전체에 반복하는 것**이다. RNN의 장점과 한계는 모두 이 구조에서 시작한다.

---

## **1. 고정 길이 입력에서 sequence modeling으로의 확장**

### **1.1 시퀀스 입출력 구조의 유형**

입력과 출력 중 어느 쪽이 sequence인지에 따라 문제의 모양이 달라진다.

- **one-to-one**: image 하나에서 class 하나를 예측하는 일반적인 분류
- **one-to-many**: image 하나에서 여러 word를 생성하는 image captioning
- **many-to-one**: 여러 video frame에서 action class 하나를 예측하는 video classification
- **many-to-many, 길이 불일치**: 여러 frame에서 길이가 다른 caption을 생성하는 video captioning
- **many-to-many, 길이 일치**: 각 video frame마다 class를 예측하는 frame-level classification

![one-to-one에서 one-to-many, many-to-one, 두 종류의 many-to-many로 확장되는 sequence modeling 구조]({{ '/assets/img/posts/cs231n-lecture-7/animations/sequence-task-types.gif' | relative_url }})

이들은 서로 완전히 다른 model이 아니다. 어느 시점의 output을 loss에 연결하는지, 최초 입력 이후 무엇을 다시 입력하는지, sequence를 언제 종료하는지를 바꾸면 같은 recurrent cell로 여러 구조를 만들 수 있다.

## **2. RNN의 hidden state와 시간축 parameter sharing**

RNN은 현재 입력 $x_t$와 이전 hidden state $h_{t-1}$를 받아 새로운 state $h_t$를 만든다.

![tanh hidden update와 linear output projection으로 구성된 Vanilla RNN의 기본 수식]({{ '/assets/img/posts/cs231n-lecture-7/slides/p26-vanilla-rnn.png' | relative_url }})

$$
h_t=f_W(h_{t-1},x_t)
$$

출력이 필요한 시점에는 hidden state를 output space로 변환한다.

$$
y_t=f_{W_{hy}}(h_t)
$$

Vanilla RNN의 대표적인 형태는 다음과 같다.

$$
h_t
=
\tanh
\left(
W_{hh}h_{t-1}
+W_{xh}x_t
+b_h
\right)
$$

$$
y_t=W_{hy}h_t+b_y
$$

$W_{xh}$는 input을 hidden dimension으로 옮기고, $W_{hh}$는 이전 state를 새로운 state로 변환하며, $W_{hy}$는 hidden representation을 task의 output dimension으로 옮긴다.

![RNN의 내부 state, 시간축 unrolling, hidden state update, output generation과 shared parameter의 전체 전개]({{ '/assets/img/posts/cs231n-lecture-7/animations/rnn-state-unrolling.gif' | relative_url }})

가장 중요한 부분은 **모든 시점에서 같은 함수와 같은 parameter를 사용한다는 점**이다. Sequence 길이가 10에서 1,000으로 늘어도 parameter 수가 시간축 길이에 비례해 늘지 않는다. 대신 계산 횟수와 저장해야 하는 activation이 늘어난다.

$h_t$를 과거 입력의 완전한 저장소로 생각하면 안 된다. 고정된 hidden dimension 안에 과거의 무엇을 보존하고 무엇을 버릴지는 task와 loss를 통해 정해진다. 임의 길이의 stream을 계속 처리할 수 있다는 말과 아주 오래된 정보를 손실 없이 기억한다는 말은 다르다.

`tanh`는 출력이 $[-1,1]$에 있고 zero-centered이므로 반복 update의 값 범위를 제한하는 데 유용하다. 하지만 포화 영역의 작은 derivative는 뒤에서 볼 vanishing gradient의 원인이 되기도 한다.

## **3. Hidden state의 구체적 설계: 연속된 1 탐지기**

입력 sequence에서 현재 값과 이전 값이 모두 `1`일 때만 $y_t=1$을 내는 RNN을 손으로 설계해 보자. 이 task에 필요한 기억은 과거 전체가 아니라 **직전 입력 하나**다.

Hidden state를 다음처럼 잡는다.

$$
h_t=
\begin{bmatrix}
\text{current}_t\\
\text{previous}_t\\
1
\end{bmatrix}
$$

마지막 상수 $1$은 output에서 bias 역할을 쉽게 만들기 위한 항이다. 다음 weight를 사용하면 현재 입력을 첫 번째 원소에 기록하고, 직전 state의 첫 번째 원소를 두 번째 원소로 복사할 수 있다.

$$
W_{xh}
=
\begin{bmatrix}
1\\0\\0
\end{bmatrix},
\qquad
W_{hh}
=
\begin{bmatrix}
0&0&0\\
1&0&0\\
0&0&1
\end{bmatrix}
$$

첫 번째 row는 이전 state를 무시하고 현재 $x_t$만 받는다. 두 번째 row는 이전의 `current`를 새로운 `previous`로 이동시킨다. 세 번째 row는 상수 $1$을 유지한다.

![연속된 두 개의 1을 탐지하기 위해 hidden state에 current와 previous를 저장하고 weight matrix를 완성하는 전 과정]({{ '/assets/img/posts/cs231n-lecture-7/animations/repeated-ones-rnn.gif' | relative_url }})

Output weight를

$$
W_{hy}
=
\begin{bmatrix}
1&1&-1
\end{bmatrix}
$$

로 두고 ReLU를 적용하면

$$
y_t
=
\operatorname{ReLU}
\left(
\text{current}_t
+\text{previous}_t
-1
\right)
$$

이 된다. 두 값이 모두 1인 경우에만 괄호 안이 1이고 나머지는 0 이하이므로 논리 AND와 같은 동작이다.

이 예제에서 중요한 것은 손으로 만든 숫자 자체가 아니다. **Task를 풀기 위해 어떤 state가 필요한지 먼저 정하고, 각 matrix row를 정보의 기록·이동·유지 연산으로 읽는 관점**이 중요하다. 실제 RNN에서는 이 weight를 사람이 구성하지 않고 loss에 대한 gradient descent로 학습한다.

## **4. 시간축으로 펼친 computational graph**

RNN block의 되먹임 화살표를 시간축으로 펼치면 일반적인 acyclic computational graph가 된다. 같은 $W$가 여러 위치에 나타나지만 서로 다른 parameter 복사본이 아니라 한 parameter의 반복 사용이다.

![RNN을 시간축으로 펼친 뒤 many-to-many, many-to-one, one-to-many와 autoregressive feedback으로 확장하는 전체 computational graph]({{ '/assets/img/posts/cs231n-lecture-7/animations/rnn-computational-graphs.gif' | relative_url }})

Output과 loss를 연결하는 위치에 따라 task가 달라진다.

- **many-to-many**: 각 시점의 $y_t$에 loss $L_t$를 연결하고 전체 loss를 합산
- **many-to-one**: 마지막 hidden state, 모든 state의 pooling, 또는 선택된 state로 하나의 output 생성
- **one-to-many**: 최초 conditioning input 이후 zero vector나 이전 output을 다음 input으로 사용
- **autoregressive generation**: 이전에 생성한 $y_{t-1}$를 다음 입력 $x_t$로 되먹임

전체 loss가

$$
L=\sum_{t=1}^{T}L_t
$$

라면 shared parameter $W$의 gradient도 각 사용 지점의 기여를 더한 값이다.

$$
\frac{\partial L}{\partial W}
=
\sum_{t=1}^{T}
\frac{\partial L_t}{\partial W}
$$

Autograd 관점에서는 같은 tensor가 graph의 여러 지점에서 사용되고 그 tensor의 `.grad`에 contribution이 누적되는 구조다. 시간마다 다른 $W_t$를 쓰면 특정 위치에 종속된 layer 집합이 되어 variable-length sequence를 같은 규칙으로 처리한다는 recurrent inductive bias가 사라진다.

## **5. Backpropagation through time**

RNN을 unroll한 graph에 [Lecture 4의 chain rule과 backpropagation](/posts/cs231n-lecture-4/)을 적용하는 것이 **Backpropagation Through Time, BPTT**다. Forward에서는 $h_1,h_2,\ldots,h_T$를 차례로 계산하고, backward에서는 마지막 시점부터 앞쪽으로 gradient를 전달한다.

전체 sequence BPTT는 모든 시점의 activation을 저장해야 하므로 sequence 길이 $T$에 비례해 activation memory가 증가한다. 또한 마지막 loss가 초반 입력에 credit을 주려면 매우 긴 chain rule 경로를 통과해야 한다.

Forward가 $h_1$부터 $h_T$까지 순차적이라고 해서 gradient를 각 시점에서 곧바로 갱신하는 것은 아니다. Full BPTT에서는 먼저 전체 forward graph를 만든 뒤 뒤에서부터 chain rule을 적용한다. 같은 $W$의 여러 사용 지점에서 나온 gradient를 모두 더한 뒤 optimizer가 한 번 parameter를 갱신한다.

### **5.1 긴 시퀀스를 위한 truncated BPTT**

Truncated BPTT는 sequence를 길이 $K$의 chunk로 나누고 각 chunk 안에서만 backward를 수행한다.

![전체 sequence의 BPTT에서 chunk별 truncated BPTT, hidden state 전달과 single-output gradient로 이어지는 전체 과정]({{ '/assets/img/posts/cs231n-lecture-7/animations/bptt-truncated-bptt.gif' | relative_url }})

Chunk 경계에서는 마지막 hidden state의 **값**을 다음 chunk의 초기 state로 넘기되, 이전 chunk로 이어지는 autograd graph는 끊는다.

```python
h = torch.zeros(
    num_layers,
    batch_size,
    hidden_size,
    device=device,
)

for x_chunk, y_chunk in stream:
    h = h.detach()
    output, h = rnn(x_chunk, h)
    loss = criterion(output, y_chunk)

    optimizer.zero_grad()
    loss.backward()
    torch.nn.utils.clip_grad_norm_(
        model.parameters(),
        max_norm=1.0,
    )
    optimizer.step()
```

위 코드는 stateful stream을 chunk 단위로 처리하는 단순한 형태다. `detach()`는 hidden value를 0으로 초기화하는 연산이 아니라 그 값의 이전 연산 이력만 제거한다. 실제 training에서는 서로 다른 sample의 state가 섞이지 않도록 batch 구성과 sequence boundary도 함께 관리해야 한다.

여기서 자주 혼동하는 두 가지를 분리해야 한다.

- **Forward state 전달**: 이전 chunk의 요약 정보가 다음 chunk의 prediction에 계속 사용됨
- **Gradient graph 절단**: 현재 loss가 $K$보다 훨씬 이전 시점에 직접 credit을 주지는 못함

따라서 truncated BPTT는 full BPTT의 정확한 대체가 아니라 memory와 credit-assignment 길이 사이의 trade-off다. 마지막 시점에만 loss가 있는 many-to-one task에서도 중간 state는 upstream gradient를 받지만, graph를 끊은 경계 너머로는 전달되지 않는다.

## **6. Character-level language model**

문자 vocabulary가 `[h, e, l, o]`이고 training sequence가 `hello`라고 하자. 각 시점의 input은 현재 문자이고 target은 다음 문자다.

$$
(h\rightarrow e),
\quad
(e\rightarrow l),
\quad
(l\rightarrow l),
\quad
(l\rightarrow o)
$$

RNN은 이전 hidden state와 현재 문자를 이용해 다음 문자의 logits를 만들고 softmax로 probability distribution을 얻는다. Training에서는 실제 이전 문자를 입력하는 teacher forcing을 사용할 수 있고, inference에서는 sampling한 문자를 다음 입력으로 되먹인다.

![hello의 one-hot 입력과 next-character target에서 autoregressive sampling과 embedding lookup으로 이어지는 character-level language model]({{ '/assets/img/posts/cs231n-lecture-7/animations/character-language-model.gif' | relative_url }})

### **6.1 One-hot vector와 embedding lookup의 관계**

Vocabulary 크기가 $V$, embedding dimension이 $D$일 때 embedding matrix를 $E\in\mathbb{R}^{D\times V}$라 하자. 문자 $k$의 one-hot vector $e_k$를 곱하면

$$
Ee_k=E_{:,k}
$$

처럼 matrix의 $k$번째 column 하나만 선택된다. 실제 구현에서 거대한 one-hot vector를 만들지 않고 index lookup을 사용하는 이유다. Embedding은 단순한 숫자 label과 달리 각 token을 학습 가능한 dense vector로 바꾼다.

Framework에 따라 embedding weight를 $E\in\mathbb{R}^{V\times D}$로 저장하고 $E_{k,:}$를 꺼내기도 한다. Row인지 column인지는 convention의 차이이며, vocabulary size와 embedding dimension이 같아야 하는 것은 아니다.

### **6.2 Autoregressive sampling과 decoding**

매 시점 최고 확률 token만 선택하는 **greedy decoding**은 같은 초기 조건에서 항상 같은 sequence를 만든다. 강의에서 강조한 것처럼 생성에서는 softmax probability에 따라 sampling할 수도 있고, 여러 후보 sequence를 유지하는 beam search 같은 방법도 사용할 수 있다.

다만 sampling한 token이 다음 입력이 되므로 초반의 잘못된 선택이 이후 state와 출력 분포를 바꿀 수 있다. Training에서는 정답 prefix를 보지만 inference에서는 자기 출력을 본다는 차이가 exposure bias의 출발점이다.

이 next-token objective에는 사람이 붙인 별도 class label이 필요하지 않다. 원문 sequence 자체를 한 칸 이동하면 input과 target pair가 만들어진다. 대규모 text를 supervision으로 바꾸기 쉬운 이유이며, character 대신 subword token을 사용해도 기본 구조는 같다.

Andrej Karpathy의 작은 character RNN은 112줄의 Python으로도 Shakespeare 문체와 C 코드의 local pattern을 학습할 수 있음을 보여 준다. 여기서 중요한 것은 생성문이 사실을 이해했다는 결론이 아니라, **next-token prediction만으로도 syntax, indentation, quote와 같은 sequence regularity가 hidden state에 나타날 수 있다는 점**이다.

## **7. Hidden state에서 나타나는 해석 가능한 cell**

Hidden state의 모든 dimension이 사람이 이해할 수 있는 의미를 갖는 것은 아니다. 많은 activation은 뚜렷한 pattern이 없지만, 일부 cell은 특정 구조와 강하게 대응한다.

![무작위 activation에서 quote, line length, if statement, comment와 code depth를 추적하는 interpretable RNN cell의 전체 비교]({{ '/assets/img/posts/cs231n-lecture-7/animations/interpretable-rnn-cells.gif' | relative_url }})

강의의 시각화에서는 한 hidden dimension의 activation을 character 위치마다 색으로 표시한다.

- quote가 열린 뒤 켜지고 닫힐 때 꺼지는 cell
- 줄의 끝에 가까워질수록 일정하게 변하는 cell
- `if` statement 내부를 추적하는 cell
- quote나 comment block을 추적하는 cell
- code indentation depth와 함께 변하는 cell

이는 앞의 반복 1 탐지기에서 `previous`를 저장하도록 손으로 만든 state가 학습을 통해 자동으로 발견된 것과 닮았다. 그러나 한 cell의 상관관계만으로 causal mechanism을 단정해서는 안 된다. 분산된 여러 dimension이 함께 같은 정보를 표현할 수도 있고, 관찰한 입력 범위 밖에서는 pattern이 깨질 수도 있다.

## **8. RNN의 계산 특성과 장기 의존성 한계**

![임의 길이 입력, shared weight와 sequential computation, fixed-size hidden state의 장단점을 비교한 RNN trade-off]({{ '/assets/img/posts/cs231n-lecture-7/slides/p77-rnn-tradeoffs.png' | relative_url }})

RNN은 같은 cell을 반복하므로 임의 길이의 stream을 처리할 수 있고, sequence가 길어져도 model parameter 수는 증가하지 않는다. 한 inference step의 state update 비용도 sequence 전체 길이와 무관한 고정 크기 연산으로 볼 수 있다.

반면 $h_t$를 구하려면 $h_{t-1}$가 필요하므로 시간축 계산을 순차적으로 수행해야 한다. Training에서 모든 token을 동시에 처리하기 어렵고, 긴 sequence의 activation graph는 memory를 많이 사용한다. 무엇보다 유한한 hidden vector 하나에 과거 정보를 계속 압축하므로 오래된 세부 정보에 접근하기 어렵다.

따라서 "context window가 명시적으로 없다"는 장점은 "무한한 과거를 완벽히 기억한다"는 뜻이 아니다. 이론적으로 오래된 정보가 state에 남을 수 있지만, 실제 보존 여부는 hidden capacity, recurrent dynamics, optimization에 달려 있다.

## **9. Image captioning을 통한 vision과 sequence의 연결**

Image captioning은 CNN이 만든 visual representation을 RNN의 sequence generation에 연결한다. Pretrained CNN의 class score 대신 penultimate feature $v$를 사용하고, 이를 hidden-state update의 conditioning signal로 넣을 수 있다.

$$
h_t
=
\tanh
\left(
W_{xh}x_t
+W_{hh}h_{t-1}
+W_{ih}v
\right)
$$

`<START>` token으로 생성을 시작하고, 매 시점 word를 sampling해 다음 입력으로 넣으며, `<END>` token이 나오면 종료한다.

![CNN feature 추출에서 START token, straw와 hat의 autoregressive sampling, END token 종료까지 이어지는 image captioning pipeline]({{ '/assets/img/posts/cs231n-lecture-7/animations/image-captioning-pipeline.gif' | relative_url }})

이 구조는 [Lecture 6의 transfer learning](/posts/cs231n-lecture-6/)과도 연결된다. ImageNet classifier의 마지막 class head를 버리고 그 앞의 feature를 다른 task의 입력 representation으로 재사용한다.

### **9.1 Captioning 결과와 failure case**

잘 작동하는 예에서는 주요 object와 action을 자연스러운 문장으로 묶는다.

![image captioning model이 생성한 고양이, 개, 곰, 사람과 스포츠 장면의 caption 예시]({{ '/assets/img/posts/cs231n-lecture-7/slides/p90-captioning-results.png' | relative_url }})

하지만 failure case는 model이 pixel evidence만 읽는 것이 아니라 training distribution의 co-occurrence를 강하게 사용한다는 사실을 보여 준다.

![fur coat를 cat으로, beach 장면을 surfboard로, 손의 물체를 computer mouse로 잘못 연결한 image captioning failure case]({{ '/assets/img/posts/cs231n-lecture-7/slides/p91-captioning-failures.png' | relative_url }})

Beach와 surfboard가 자주 함께 나타나면 실제로 surfboard가 없어도 그 단어를 생성할 수 있다. 손에 든 물체의 국소 shape보다 "사람이 이런 자세로 손에 들고 있는 물체"라는 dataset prior가 앞설 수도 있다. 이는 단순한 문법 오류가 아니라 visual evidence와 language prior 사이의 균형 문제다. 현대 vision-language model에서도 장면과 자주 동반되는 object를 실제로 존재하는 것처럼 말하는 hallucination은 같은 관점에서 점검할 수 있다.

## **10. Multilayer RNN의 시간축과 깊이축**

RNN도 여러 layer를 쌓을 수 있다. Layer $l$의 hidden state는 같은 layer의 이전 시점 state와 아래 layer의 현재 시점 output을 함께 받는다.

$$
h_t^{(l)}
=
f_{W^{(l)}}
\left(
h_{t-1}^{(l)},
h_t^{(l-1)}
\right)
$$

![시간축과 깊이축으로 쌓인 multilayer RNN의 계산 격자]({{ '/assets/img/posts/cs231n-lecture-7/slides/p95-multilayer-rnn.png' | relative_url }})

같은 layer 안에서는 시간축으로 weight를 공유하지만 서로 다른 layer는 별도 parameter를 가진다. 오른쪽 위 state를 계산하려면 왼쪽의 이전 시점들과 아래쪽 layer의 현재 시점들이 먼저 계산되어야 한다. 깊이축과 시간축이 결합되면서 gradient 경로도 길어진다.

## **11. Vanilla RNN의 gradient 소실과 폭발**

Vanilla RNN의 pre-activation을

$$
a_t=W_{hh}h_{t-1}+W_{xh}x_t+b_h
$$

라 두면 인접한 hidden state 사이의 Jacobian은

$$
\frac{\partial h_t}{\partial h_{t-1}}
=
\operatorname{diag}
\left(
\tanh'(a_t)
\right)
W_{hh}
$$

다. 마지막 loss가 오래전 state에 영향을 주려면 이 Jacobian을 여러 번 곱해야 한다.

$$
\frac{\partial L_T}{\partial h_k}
=
\frac{\partial L_T}{\partial h_T}
\prod_{t=k+1}^{T}
\frac{\partial h_t}{\partial h_{t-1}}
$$

![단일 recurrent update의 Jacobian에서 시간축 반복 곱, tanh 포화, singular value와 gradient clipping으로 이어지는 gradient flow]({{ '/assets/img/posts/cs231n-lecture-7/animations/vanilla-rnn-gradient-flow.gif' | relative_url }})

`tanh`의 derivative는 최대 1이고 포화 영역에서는 0에 가깝다. 여기에 $W_{hh}$가 반복해서 곱해진다. 전체 Jacobian의 지배적인 크기가 계속 1보다 작으면 gradient가 지수적으로 작아지고, 1보다 크면 폭발할 수 있다. 비선형성을 제거한 단순한 경우에는 $W_{hh}^{T-k}$의 singular value가 이 현상을 직접 보여 준다.

Vanishing gradient는 초반 정보가 forward state에서 즉시 사라진다는 말과 같지 않다. 핵심은 **멀리 있는 원인에 loss가 학습 신호를 전달하기 어려워져, 그 정보를 오래 보존하는 recurrent dynamics 자체를 배우기 어렵다는 점**이다.

### **11.1 Exploding gradient를 위한 norm clipping**

Exploding gradient에는 global norm clipping을 적용할 수 있다. Gradient vector $g$와 threshold $\tau$에 대해

$$
g
\leftarrow
\begin{cases}
g,
&\lVert g\rVert_2\le\tau\\[4pt]
\tau\dfrac{g}{\lVert g\rVert_2},
&\lVert g\rVert_2>\tau
\end{cases}
$$

로 크기만 제한하고 방향은 유지한다. Clipping은 parameter update가 한 번에 폭주하는 것을 막지만, 이미 0에 가까워진 gradient를 되살리지는 않는다. Exploding과 vanishing은 대칭적으로 보이지만 같은 처방으로 해결되지 않는다.

## **12. LSTM의 gate와 cell state**

LSTM은 하나의 hidden state에 모든 역할을 맡기지 않고, 외부로 드러나는 hidden state $h_t$와 장기 정보 경로인 cell state $c_t$를 분리한다. 이전 hidden state와 현재 input을 붙여 네 개의 vector를 한 번에 계산한다.

$$
\begin{bmatrix}
i_t\\f_t\\o_t\\g_t
\end{bmatrix}
=
\begin{bmatrix}
\sigma\\\sigma\\\sigma\\\tanh
\end{bmatrix}
W
\begin{bmatrix}
h_{t-1}\\x_t
\end{bmatrix}
$$

$$
c_t
=
f_t\odot c_{t-1}
+i_t\odot g_t
$$

$$
h_t
=
o_t\odot\tanh(c_t)
$$

![Vanilla RNN에서 LSTM의 four gates, cell state update와 시간축 gradient highway로 이어지는 전체 전개]({{ '/assets/img/posts/cs231n-lecture-7/animations/lstm-gates-gradient-flow.gif' | relative_url }})

### **12.1 Input·forget·output gate와 candidate state**

- $i_t$: candidate 중 cell state에 새로 기록할 양
- $f_t$: 이전 cell state에서 유지할 양
- $o_t$: 현재 cell state를 hidden state로 드러낼 양
- $g_t$: 새로 기록할 candidate content

강의 슬라이드에는 $g_t$가 `gate gate(?)`로 적혀 있지만, sigmoid gate가 아니라 $\tanh$를 거친 **candidate state**로 보는 편이 정확하다. Gate는 0과 1 사이의 값으로 정보 흐름을 조절하고, candidate는 기록할 내용을 제공한다.

### **12.2 Cell state를 통한 gradient 경로**

직접적인 cell-state 경로만 보면

$$
\frac{\partial c_t}{\partial c_{t-1}}=f_t
$$

다. Vanilla RNN처럼 매 시점 recurrent matrix 전체와 `tanh` derivative를 반드시 곱하는 대신 element-wise forget gate를 통과한다. $f_t\approx1$이고 $i_t\approx0$이면 기존 cell state와 gradient를 오랫동안 보존하기 쉬워진다.

이 additive path는 [Lecture 6의 ResNet skip connection](/posts/cs231n-lecture-6/)과 닮았다. 깊은 network에서 layer를 건너뛰는 identity path가 있듯, LSTM은 긴 시간축에서 복잡한 transform을 우회하는 state path를 제공한다.

![LSTM의 cell-state 경로와 Highway Network 및 ResNet의 additive shortcut 사이의 연결]({{ '/assets/img/posts/cs231n-lecture-7/slides/p121-lstm-resnet-connection.png' | relative_url }})

### **12.3 Vanishing gradient 완화의 범위**

LSTM이 vanishing gradient를 수학적으로 없애는 것은 아니다.

![LSTM이 정보 보존을 쉽게 만들지만 vanishing과 exploding gradient의 부재를 보장하지 않는다는 정리]({{ '/assets/img/posts/cs231n-lecture-7/slides/p119-lstm-limit.png' | relative_url }})

Forget gate가 계속 1보다 작으면 그 곱도 결국 작아질 수 있고, 다른 경로에는 여전히 nonlinear transform과 matrix multiplication이 있다. LSTM의 장점은 필요한 정보에 대해 $f_t$를 1에 가깝게, 불필요한 새 기록에 대해 $i_t$를 0에 가깝게 만드는 **학습 가능한 보존 경로**를 제공한다는 데 있다.

## **13. 현대적 state-space model과 recurrent computation**

![RWKV, S4와 Mamba를 RNN의 hidden state, 임의 길이 입력과 linear sequence scaling에 연결한 modern RNN 슬라이드]({{ '/assets/img/posts/cs231n-lecture-7/slides/p122-modern-rnns.png' | relative_url }})

Transformer 이후에도 state를 순차적으로 갱신하는 아이디어는 사라지지 않았다. RWKV와 structured state-space model, Mamba 같은 계열은 긴 sequence에서 attention의 quadratic cost를 줄이면서 선택적으로 정보를 전달하는 방법을 탐구한다.

다만 RNN과 state-space model을 완전한 동의어로 보면 안 된다. 둘은 hidden state update라는 공통 관점을 가지지만 parameterization, training algorithm, 병렬화 방식이 다르다. Mamba는 input에 따라 state-space parameter가 달라지는 selective mechanism과 hardware-aware scan을 사용해 sequence length에 대한 linear scaling을 목표로 한다.

여기서 Lecture 7과의 연결은 구체적 구현보다 문제의 형태다.

$$
\text{현재 input}
+
\text{이전 state}
\longrightarrow
\text{새 state}
$$

어떤 정보를 유지하고 버릴지 선택하면서 긴 sequence를 효율적으로 처리하려는 질문은 Vanilla RNN, LSTM, 현대 SSM에 공통으로 남아 있다.

## **14. PyTorch를 이용한 shape와 state 검산**

`batch_first=True`인 `nn.RNN`에서 input shape은 `(N, T, D_in)`이고 output은 모든 시점의 마지막 layer hidden state를 담는다.

```python
import torch
from torch import nn

N, T = 8, 20
input_size = 32
hidden_size = 64
num_layers = 2

x = torch.randn(N, T, input_size)

rnn = nn.RNN(
    input_size=input_size,
    hidden_size=hidden_size,
    num_layers=num_layers,
    nonlinearity="tanh",
    batch_first=True,
)

output, h_n = rnn(x)

print(output.shape)  # (8, 20, 64)
print(h_n.shape)     # (2, 8, 64)
```

`output[:, t]`는 시점 $t$의 **마지막 layer** output이고, `h_n[l]`은 각 layer $l$의 마지막 hidden state다. `output[:, -1]`과 `h_n[-1]`은 단방향 RNN에서 같은 마지막-layer state를 가리킨다.

LSTM은 hidden state와 cell state를 함께 반환한다.

```python
lstm = nn.LSTM(
    input_size=input_size,
    hidden_size=hidden_size,
    num_layers=num_layers,
    batch_first=True,
)

output, (h_n, c_n) = lstm(x)

print(output.shape)  # (8, 20, 64)
print(h_n.shape)     # (2, 8, 64)
print(c_n.shape)     # (2, 8, 64)
```

Sequence length $T$는 output의 시간축을 바꾸지만 weight tensor의 shape는 바꾸지 않는다. 반면 `hidden_size`와 `num_layers`는 model parameter 수와 state shape를 바꾼다. Variable-length batch에서는 padding된 위치를 loss에서 mask하거나 `pack_padded_sequence`를 사용할 수 있다.

## **15. 정리**

RNN은 현재 input과 이전 hidden state로 새로운 state를 만들고, 같은 parameter를 시간축 전체에 공유한다. 이 구조 덕분에 길이가 달라지는 sequence를 처리하면서 parameter 수를 일정하게 유지할 수 있다. Task에 따라 output과 loss를 어느 시점에 연결할지, 이전 output을 다시 입력할지 선택해 many-to-one, one-to-many와 many-to-many 구조를 만든다.

BPTT는 unrolled graph에 chain rule을 적용하고 shared weight의 모든 사용 지점에서 gradient를 합산한다. Truncated BPTT는 hidden state 값은 계속 전달하면서 gradient graph의 길이를 제한해 memory를 줄이지만, 먼 과거에 대한 credit assignment도 함께 제한한다.

Character-level language model과 image captioning은 hidden state가 text history와 visual feature를 autoregressive generation에 연결하는 방식을 보여 준다. 동시에 fixed-size state의 bottleneck, sequential computation, 반복 Jacobian 곱에 따른 vanishing·exploding gradient가 Vanilla RNN의 핵심 한계다.

LSTM은 input, forget, output gate와 candidate state를 이용해 cell state에 무엇을 쓰고 유지할지 선택한다. Cell state의 additive path는 장기 정보와 gradient를 보존하기 쉽게 만들지만 완전한 보장은 아니다. 현대 state-space model도 구현은 달라졌지만, **state를 갱신하며 필요한 정보를 선택적으로 통과시키는 sequence modeling의 핵심 질문**을 이어 간다.

$$
\boxed{
\begin{aligned}
&\text{shared recurrent update}\\
+{}&\text{hidden state}\\
+{}&\text{time-unrolled gradient}\\
= {}&\text{sequence model}
\end{aligned}
}
$$
