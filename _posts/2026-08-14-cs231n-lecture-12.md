## **0. 이 글의 목표**

[Lecture 11의 대규모 분산 학습](/posts/cs231n-lecture-11/)은 큰 model을 여러 GPU에서 학습시키는 계산 문제를 다뤘다. 이번에는 계산 자원이 충분하더라도 대규모 수작업 label이 없을 때, data 자체에서 학습 신호를 만드는 방법을 다룬다.

[Pixel space의 거리](/posts/cs231n-lecture-2/#2-가장-단순한-데이터-중심-분류기-nearest-neighbor)는 조명이나 시점 변화에 쉽게 흔들린다. 반면 잘 학습된 feature space에서는 같은 의미의 image가 가까워지고 다른 의미의 image가 멀어진다. `Feature`, `embedding`, `latent representation`은 구체적인 tensor와 사용 위치는 달라도, 입력을 downstream에서 재사용할 좌표로 바꾼다는 공통점을 갖는다.

이번 글의 핵심 질문은 다음과 같다.

- 사람이 label을 붙이지 않고도 target을 만드는 방법
- Pretext-task accuracy와 representation 품질의 차이
- Rotation·jigsaw·inpainting·colorization이 각각 강제하는 시각 정보
- MAE가 75%의 patch를 가리면서도 효율적으로 학습되는 구조
- InfoNCE를 positive 식별을 위한 $N$-way classification으로 보는 관점
- SimCLR의 augmentation·projection head·large batch가 맡는 역할
- MoCo의 queue와 momentum encoder가 함께 필요한 이유
- CPC의 future prediction과 DINO의 negative-free self-distillation

핵심은 **정답을 사람이 새로 만드는 대신 data 안의 구조로 학습 문제를 만들고, 그 문제를 푸는 과정에서 downstream task에 재사용할 representation을 얻는 것**이다.

## **1. 라벨 비용과 자기지도 학습의 출발**

### **1.1 Pretext task와 downstream task의 분리**

자기지도 학습(self-supervised learning)은 학습 신호가 전혀 없는 학습이 아니다. 사람이 만든 semantic label 대신 입력 변환, 가려진 영역, 같은 instance의 다른 view, 시간적으로 이어지는 frame처럼 **data 자체에서 target을 자동 생성**한다. Loss는 여전히 classification, regression, reconstruction처럼 익숙한 supervised objective일 수 있다.

![대규모 라벨의 병목에서 pretext task·trained encoder·downstream transfer·linear evaluation으로 이어지는 자기지도 학습 구조]({{ '/assets/img/posts/cs231n-lecture-12/animations/self-supervised-pretext-downstream.gif' | relative_url }})

전체 구조는 두 단계로 나뉜다.

1. Label이 없는 큰 dataset으로 pretext task를 구성하고 encoder $f_\theta$를 학습한다.
2. Pretext head는 버리고 encoder를 downstream task의 feature extractor로 재사용한다.

입력 $x$에서 자동 target $y_{\text{pre}}=T(x)$를 만들고 head $g_\phi$를 붙이면 pretraining objective는

$$
\min_{\theta,\phi}
\mathbb{E}_{x\sim\mathcal D_u}
\left[
\ell_{\text{pre}}
\bigl(g_\phi(f_\theta(x)),T(x)\bigr)
\right]
$$

로 쓸 수 있다. $\mathcal D_u$는 사람이 붙인 class label이 없는 dataset이다. Target $T(x)$는 data transformation에서 만들어지고, decoder나 classifier head는 그 target을 **예측**한다.

좋은 pretext task에는 두 조건이 필요하다.

- Target을 수작업 annotation 없이 대량으로 만들 수 있어야 한다.
- Shortcut만으로 풀리지 않고 의미 있는 시각 특징이 필요할 만큼 어려워야 한다.

자동 target이라는 사실만으로 좋은 representation이 보장되지는 않는다. JPEG artifact나 crop boundary 같은 저수준 단서만으로 정답을 맞힐 수 있다면 encoder도 그 shortcut에 머문다.

### **1.2 Linear probing과 full fine-tuning 기반 평가**

Pretext task를 잘 푸는 것과 representation이 좋은 것은 다르다. 실제 목표는 rotation accuracy나 pixel reconstruction score가 아니라 classification·detection·segmentation 같은 [downstream spatial task](/posts/cs231n-lecture-9/#1-image-classification-이후의-spatial-prediction)에서의 재사용성이다.

가장 흔한 두 평가 방식은 다음과 같다.

| 평가 방식 | Encoder | 새 head | 측정 범위 |
|---|---|---|---|
| Linear probing | 고정 | Linear layer만 학습 | Feature에 이미 선형적으로 드러난 정보 |
| Full fine-tuning | 함께 학습 | 함께 학습 | Representation 품질과 새 task 적응력 |

Linear probe가 좋은 성능을 낸다면 class 정보가 frozen feature space에서 이미 간단한 hyperplane으로 분리된다는 뜻이다. Full fine-tuning은 encoder 자체를 바꾸므로 더 높은 성능을 낼 수 있지만, 처음 representation의 순수한 품질과 task adaptation 효과가 섞인다. 이 차이는 [transfer learning 전략](/posts/cs231n-lecture-6/#9-데이터-양과-domain-차이에-따른-transfer-learning-전략)과도 연결된다.

## **2. Image transformation 기반 pretext task**

### **2.1 Rotation prediction의 visual commonsense**

Rotation prediction은 원본 image를 $0^\circ$, $90^\circ$, $180^\circ$, $270^\circ$ 중 하나로 돌리고 적용된 각도를 맞히는 4-way classification이다.

$$
y_r\in\{0,1,2,3\},
\qquad
\mathcal L_{\text{rot}}
=
-\log p_\theta(y_r\mid R_{y_r}(x))
$$

![네 방향 회전 분류에서 semi-supervised evaluation·downstream transfer·learned attention으로 이어지는 rotation pretext task]({{ '/assets/img/posts/cs231n-lecture-12/animations/rotation-pretext-task.gif' | relative_url }})

고양이의 다리와 머리, 자동차의 바퀴와 지면처럼 물체의 올바른 방향을 판단하려면 object part와 scene layout을 어느 정도 이해해야 한다는 가설이다. Rotation pretraining 뒤 얻은 feature가 적은 label의 classification이나 detection에 전이되는지가 진짜 평가다.

Rotation prediction은 rotation **invariance**가 아니라 각도를 구별하는 orientation-sensitive representation을 만든다. 이후 SimCLR에서 같은 augmentation view를 positive로 묶어 transformation invariance를 학습하는 것과 반대 방향이다.

해당 rotation 연구의 attention visualization에서는 supervised classifier가 class 판별에 필요한 일부에 집중한 반면, rotation-pretrained model은 image의 더 넓은 영역을 보는 경향이 나타났다.

### **2.2 Relative patch location과 jigsaw permutation**

Relative patch prediction은 기준 patch와 주변 patch를 뽑고 주변 patch가 기준의 어느 방향에 있었는지 맞힌다. Jigsaw는 image를 여러 tile로 자른 뒤 섞고 원래 arrangement를 식별한다.

![상대 patch 위치 예측에서 jigsaw permutation classification과 downstream transfer로 이어지는 spatial pretext task]({{ '/assets/img/posts/cs231n-lecture-12/animations/patch-location-jigsaw.gif' | relative_url }})

두 task 모두 local texture 하나만 보는 대신 part 사이의 spatial configuration을 학습하게 만든다. 다만 tile 경계의 색수차, interpolation artifact, chromatic aberration처럼 permutation을 우회적으로 알려 주는 단서가 생길 수 있으므로 crop 간 gap, jitter, color normalization 같은 설계가 중요하다.

$3\times3$ jigsaw에는 이론상 $9!$개의 permutation이 있지만 모든 조합을 class로 쓰지는 않는다. 서로 충분히 Hamming distance가 큰 permutation subset을 골라 classification target으로 사용한다.

### **2.3 Inpainting의 다중 정답과 reconstruction blur**

Inpainting은 image의 일부를 mask하고 주변 context만으로 빠진 pixel을 복원한다. Mask $M\in\{0,1\}^{H\times W}$에서 1이 가려진 위치라면 reconstruction loss는

$$
\mathcal L_{\text{rec}}
=
\left\|
M\odot
\left(x-G_\theta((1-M)\odot x)\right)
\right\|_2^2
$$

로 쓸 수 있다.

![가려진 영역의 예측에서 encoder-decoder reconstruction·adversarial objective·downstream transfer로 이어지는 context encoder]({{ '/assets/img/posts/cs231n-lecture-12/animations/context-encoder-inpainting.gif' | relative_url }})

가려진 창문 안에는 사람, 가구, 벽처럼 가능한 답이 여러 개다. Pixel-wise L2는 서로 다른 가능한 결과의 평균을 선호하므로 흐릿한 복원을 만들기 쉽다. Context Encoder가 reconstruction loss와 adversarial objective를 함께 사용한 이유는 단순히 edge를 선명하게 하는 데 있지 않다. 가능한 여러 답 중 natural-image distribution에 가까운 결과를 선호하게 만드는 역할이다.

Discriminator $D$는 real image와 completion을 더 잘 구별하도록 갱신되고, generator $G$는 reconstruction과 adversarial loss를 함께 최소화한다. 이 결합은 **다중 정답 문제에서 point estimate loss가 평균으로 수렴하는 한계**를 보완한다.

### **2.4 Cross-channel colorization과 Split-Brain Autoencoder**

Colorization은 RGB를 Lab color space로 바꾼 뒤 luminance $L$에서 chrominance $ab$를 예측한다.

$$
L\in\mathbb R^{H\times W\times1}
\xrightarrow{f_\theta}
\widehat{ab}\in\mathbb R^{H\times W\times2}
$$

![Lab color prediction에서 cross-channel prediction·Split-Brain Autoencoder·transfer 결과로 이어지는 colorization pretext task]({{ '/assets/img/posts/cs231n-lecture-12/animations/image-colorization-split-brain.gif' | relative_url }})

회색 image를 자연스럽게 칠하려면 sky, grass, skin, vehicle처럼 object와 material을 구분해야 한다. 하지만 하나의 luminance에 여러 색이 가능하므로 regression만 쓰면 평균적인 색으로 흐려질 수 있다. 실제 방법은 $ab$ color를 quantized class로 바꾸고 class-rebalancing classification을 쓰는 등 ambiguity를 다룬다.

일반 colorization encoder는 $L$만 입력으로 보므로 원 image의 chrominance 정보를 representation에 사용하지 못한다. Split-Brain Autoencoder는 두 branch를 둔다.

$$
\widehat{ab}=F_1(L),
\qquad
\widehat{L}=F_2(ab)
$$

한 branch는 luminance에서 color를, 다른 branch는 color에서 luminance를 예측하고 downstream에서는 두 feature를 concatenate한다. 수동 label은 없지만 반대 channel이 이미 원 image 안에 있으므로 target을 자동으로 얻는다.

### **2.5 Video color propagation과 tracking의 출현**

[Video representation](/posts/cs231n-lecture-10/#9-video-representation의-시각화)에서는 시간에 따라 변하는 pattern을 직접 다뤘다. Video colorization은 첫 reference frame의 색을 이후 grayscale frame에 일관되게 옮기는 문제로 correspondence를 학습한다.

Reference pixel $i$와 target pixel $j$의 feature를 $f_i$, $f_j$라고 하면 affinity는

$$
A_{ij}
=
\frac{
\exp(f_i^\top f_j)
}{
\sum_k\exp(f_k^\top f_j)
}
$$

이고 reference color $c_i$를 target으로 옮긴 결과는

$$
\widehat c_j
=
\sum_i A_{ij}c_i
$$

다. 각 target 위치가 reference의 어느 위치를 가리킬지 학습한다는 점에서 [attention의 weighted sum](/posts/cs231n-lecture-8/#3-querykeyvalue를-이용한-attention의-일반화)과 같은 구조다.

![Reference와 target frame의 feature affinity에서 reference color weighted sum과 color reconstruction loss로 이어지는 video colorization]({{ '/assets/img/posts/cs231n-lecture-12/animations/video-colorization-correspondence.gif' | relative_url }})

정지된 결과 image만 보면 색이 한 frame 안에서 그럴듯한지는 알 수 있지만, 움직이는 동안 같은 사람과 물체에 색이 유지되는지는 판단하기 어렵다.

![Reference frame의 색이 움직이는 target frame에 시간적으로 일관되게 전파되는 video colorization 결과]({{ '/assets/img/posts/cs231n-lecture-12/animations/video-colorization-qualitative.gif' | relative_url }})

이 모델은 optical-flow label이나 tracking annotation으로 학습되지 않았다. Color를 제대로 복사하려면 같은 physical region을 찾아야 하므로 soft correspondence가 학습되고, 이 affinity에 color 대신 첫 frame의 segmentation mask나 pose keypoint를 넣으면 tracking이 나타난다.

![Colorization으로 학습한 correspondence를 이용한 움직이는 segmentation mask와 pose keypoint의 전파]({{ '/assets/img/posts/cs231n-lecture-12/animations/video-colorization-tracking.gif' | relative_url }})

즉 colorization은 output task이면서 동시에 **시간을 가로지르는 pointer를 학습하는 pretext task**다.

## **3. Masked Autoencoder의 비대칭 reconstruction**

[Vision Transformer의 patch tokenization](/posts/cs231n-lecture-8/#9-vision-transformer의-patch-tokenization)을 reconstruction pretraining에 적용하면 Masked Autoencoder(MAE)가 된다. Image를 $P\times P$ patch로 나누어 $N=HW/P^2$개의 token을 만든 뒤 많은 patch를 가리고 빠진 pixel을 복원한다.

### **3.1 높은 masking ratio와 visible-token encoder**

MAE의 대표 설정은 patch의 약 75%를 random masking하고 25%만 encoder에 넣는다.

![75% patch masking에서 visible-token encoder·lightweight decoder·masked-only loss·linear probe와 ablation으로 이어지는 MAE 구조]({{ '/assets/img/posts/cs231n-lecture-12/animations/masked-autoencoder.gif' | relative_url }})

순서는 다음과 같다.

1. Image를 patch embedding $X\in\mathbb R^{N\times D}$로 바꾼다.
2. Random permutation으로 visible index $V$와 masked index $M$을 나눈다.
3. Encoder에는 $X_V$만 넣는다.
4. Encoder output과 학습 가능한 shared mask token을 원래 위치에 맞춰 합친다.
5. Positional embedding을 더한 전체 sequence를 lightweight decoder에 넣는다.

Masking ratio를 $r$이라 하면 visible token 수는 $N_v=(1-r)N$이다. Encoder output은 $[N_v,D_e]$, decoder sequence는 $[N,D_d]$, reconstruction head의 output은 patch마다 pixel을 펼친 $[N,P^2C]$ shape를 갖는다.

중요한 점은 encoder에 mask token이 들어가지 않는다는 것이다. Mask token은 encoder가 출력하는 평균 patch도 아니고, masked position을 decoder에 표시하는 학습 가능한 placeholder다. 각 위치의 차이는 positional embedding이 알려 준다.

Visible token이 $0.25N$개라면 encoder attention matrix의 면적은

$$
(0.25N)^2
=
\frac{1}{16}N^2
$$

가 된다. 실제 전체 FLOPs는 MLP와 embedding도 포함하므로 정확히 16배 감소한다고 단정할 수는 없지만, 가장 비싼 큰 encoder가 일부 token만 처리한다는 사실이 계산 절감의 핵심이다. 높은 masking ratio는 복원을 어렵게 만들어 넓은 context를 요구하는 동시에 encoder cost도 줄인다.

### **3.2 Lightweight decoder와 masked-patch loss**

Patch $p_i$와 reconstruction $\widehat p_i$에 대한 loss는 masked position에만 계산한다.

$$
\mathcal L_{\text{MAE}}
=
\frac{1}{|M|}
\sum_{i\in M}
\left\|
\widehat p_i-p_i
\right\|_2^2
$$

Visible patch까지 복원 loss에 넣지 않으므로 model은 이미 본 pixel을 복사하는 쉬운 경로에 보상받지 않는다. Decoder는 mask token을 포함한 전체 token을 처리하지만 작고 얕게 만들 수 있고, pretraining이 끝나면 버린다. Downstream에서 남는 것은 큰 encoder다.

Encoder와 decoder는 반드시 대칭일 필요가 없다. Rotation prediction의 linear head도 넓은 의미의 pretext head이고, Context Encoder와 MAE의 decoder도 encoder와 깊이·width가 다를 수 있다. MAE에서는 이 비대칭성이 representation 학습과 reconstruction 계산을 분리한다.

MAE의 75% masking은 해당 설계의 ablation에서 semantic representation과 계산 효율 사이의 좋은 지점으로 선택됐다. Patch size, decoder capacity, target normalization, training schedule이 달라지면 최적점도 달라질 수 있다.

## **4. Task-specific pretext의 한계와 contrastive objective**

Rotation, jigsaw, inpainting, colorization은 각각 유용한 구조를 학습하게 만들지만 representation이 특정 pretext task에 묶일 수 있다.

![Rotation·jigsaw·inpainting·colorization의 task-specific 한계에서 same-object attraction과 different-object repulsion으로 이어지는 contrastive objective]({{ '/assets/img/posts/cs231n-lecture-12/animations/pretext-to-contrastive-transition.gif' | relative_url }})

- Rotation은 orientation과 object layout에 민감한 특징을 유도한다.
- Jigsaw는 part configuration을 보지만 tile artifact를 shortcut으로 쓸 수 있다.
- Inpainting은 texture reconstruction에 치우칠 수 있다.
- Colorization은 material과 object semantics를 요구하지만 color ambiguity가 남는다.

Contrastive learning은 특정 변환의 정답을 맞히는 대신 **어떤 두 view를 같은 것으로 보고 어떤 sample을 다른 것으로 볼지**를 직접 정의한다. 같은 image에서 만든 두 augmentation은 positive pair, 다른 image에서 나온 representation은 negative pair로 둔다.

$$
s(f(x),f(x^+))
\gg
s(f(x),f(x^-))
$$

여기서 augmentation은 단순한 regularization이 아니라 학습할 invariance 자체를 정한다. [Label-preserving augmentation](/posts/cs231n-lecture-6/#83-label-보존을-전제로-한-augmentation)이 너무 약하면 pixel shortcut이 남고, 너무 강하면 positive 두 view에서 class identity까지 사라진다. Crop이 dog의 머리와 배경만 각각 남긴다면 둘을 같은 instance로 묶는 신호 자체가 모호해질 수 있다.

## **5. InfoNCE의 N-way classification 관점**

### **5.1 Positive·negative pair와 score function**

Query $q=f(x)$, positive key $k^+=f(x^+)$, $K-1$개의 negative key $k_r^-$가 있다고 하자. Similarity $s$와 temperature $\tau$를 쓰는 InfoNCE loss는

$$
\mathcal L_{\text{NCE}}
=
-\log
\frac{
\exp(s(q,k^+)/\tau)
}{
\exp(s(q,k^+)/\tau)
+
\sum_{r=1}^{K-1}
\exp(s(q,k_r^-)/\tau)
}
$$

다.

![Reference·positive·negative pair에서 score function·InfoNCE 분자와 분모·N-way softmax·mutual-information bound로 이어지는 유도]({{ '/assets/img/posts/cs231n-lecture-12/animations/contrastive-infonce.gif' | relative_url }})

분자는 정답 positive의 logit이고 분모는 positive와 모든 negative 후보의 합이다. 따라서 이 loss는 $K$개의 candidate 중 positive index를 class label로 두는 [softmax cross-entropy](/posts/cs231n-lecture-2/#10-softmax-classifier와-cross-entropy)다. 별도의 새로운 optimization primitive라기보다 candidate set을 class axis로 바꾼 classification이다.

Embedding을 L2-normalize하면 dot product는 cosine similarity가 된다.

$$
s(u,v)
=
\frac{u^\top v}{\|u\|_2\|v\|_2}
$$

Normalize하지 않으면 model이 direction보다 vector norm을 키워 logit을 높이는 쉬운 경로를 사용할 수 있다.

### **5.2 Temperature와 mutual-information bound**

Temperature $\tau$는 similarity logit의 scale을 조절한다.

- 작은 $\tau$: distribution이 날카로워지고 hard negative의 영향이 커진다.
- 큰 $\tau$: 후보 확률이 평평해지고 gradient가 여러 negative에 퍼진다.

$\tau$가 너무 작으면 우연히 가까운 false negative 하나가 optimization을 지배할 수 있고, 너무 크면 positive와 negative의 차이가 희석된다.

표준 sampling 가정에서는

$$
I(X;Y)
\ge
\log K-\mathbb E[\mathcal L_{\text{NCE}}]
$$

형태의 mutual-information lower bound를 얻는다. Negative candidate 수 $K-1$이 늘면 bound의 ceiling이 커지지만, 큰 batch 자체가 semantic representation을 보장하지는 않는다. Positive construction, augmentation, false negative, encoder capacity와 optimization이 함께 결과를 결정한다.

## **6. SimCLR의 augmentation·projection head·large batch**

### **6.1 Two-view batch와 affinity matrix**

SimCLR은 원본 image $N$개에서 stochastic augmentation을 두 번 적용해 $2N$개의 view를 만든다. 각 view는 encoder $f$와 projection head $g$를 지난다.

$$
h_i=f(x_i),
\qquad
z_i=g(h_i)
$$

![두 augmentation view·encoder·projection head에서 2N embedding·affinity matrix·positive column label로 이어지는 SimCLR mini-batch]({{ '/assets/img/posts/cs231n-lecture-12/animations/simclr-framework.gif' | relative_url }})

$Z\in\mathbb R^{2N\times D}$를 row-wise normalize하면 affinity matrix는

$$
S=ZZ^\top\in\mathbb R^{2N\times2N}
$$

가 된다. 각 row는 한 anchor가 모든 view와 갖는 cosine similarity다. 자기 자신인 diagonal은 candidate에서 제외하고, 같은 원본 image에서 나온 paired view의 column을 정답 class로 둔다.

Anchor 하나를 기준으로 보면

- Positive 1개
- Negative $2N-2$개
- 자기 자신 1개는 제외

다. 두 방향을 모두 anchor로 사용하므로 loss는 $2N$개 row의 평균이다.

### **6.2 Representation $h$와 projection $z$의 역할 분리**

Contrastive loss는 projection 뒤의 $z$에 적용하지만 downstream task에는 projection 전의 $h$를 쓴다.

![SimCLR feature의 linear·semi-supervised evaluation과 projection head·large-batch design choice]({{ '/assets/img/posts/cs231n-lecture-12/animations/simclr-evaluation-design.gif' | relative_url }})

이 분리는 중요한 trade-off를 해결한다. Color jitter에 invariant해지려면 $z$에서는 color 정보를 버리는 편이 유리하지만, downstream task가 fine-grained color recognition이라면 $h$에는 그 정보가 남아 있는 편이 좋다. Projection head가 contrastive objective에 특화된 변환을 맡고 encoder representation은 더 넓은 정보를 유지할 수 있다.

### **6.3 In-batch negative와 memory cost**

SimCLR은 별도의 memory bank 없이 같은 global batch의 다른 view를 negative로 사용한다. Batch가 커지면 candidate가 늘지만 $2N\times2N$ similarity matrix, activation, distributed feature gathering 비용도 커진다.

[Data Parallelism](/posts/cs231n-lecture-11/#3-data-parallelism과-gradient-평균)으로 batch를 여러 GPU에 나눠도 global negative를 쓰려면 rank 사이의 embedding을 모아야 한다.

또 다른 문제는 **false negative**다. Label을 보지 않으므로 같은 semantic class의 다른 dog image도 negative가 된다. Instance discrimination에는 맞는 정의지만 class-level semantics와는 충돌할 수 있다.

## **7. MoCo의 queue와 momentum encoder**

SimCLR의 negative 수는 current minibatch 크기에 묶인다. Momentum Contrast(MoCo)는 과거 batch의 key를 FIFO queue에 저장해 dictionary 크기와 minibatch size를 분리한다.

![Query·key encoder와 FIFO queue에서 momentum update·enqueue/dequeue·MoCo v2 설계로 이어지는 Momentum Contrast]({{ '/assets/img/posts/cs231n-lecture-12/animations/moco-momentum-queue.gif' | relative_url }})

### **7.1 Query encoder의 gradient path**

두 augmentation view 중 하나는 query encoder $f_q$로, 다른 하나는 key encoder $f_k$로 보낸다.

$$
q=f_q(x^q),
\qquad
k^+=f_k(x^k)
$$

$q,k^+\in\mathbb R^{B\times C}$이고 queue를 $Q\in\mathbb R^{C\times K}$라고 하면 positive logit은 $[B,1]$, negative logit $qQ$는 $[B,K]$, 전체 InfoNCE logit은 $[B,1+K]$가 된다.

Query encoder는 InfoNCE loss의 [backward path](/posts/cs231n-lecture-4/#52-backward-pass)를 따라 optimizer로 갱신된다. Query가 positive이고 key가 negative인 구조는 아니다. Key set 안에 matching positive $k^+$ 하나와 queue에서 온 negative key들이 함께 있다.

### **7.2 Key encoder의 EMA update**

Key encoder는 loss gradient로 직접 갱신하지 않고 query encoder의 exponential moving average로 업데이트한다.

$$
\theta_k
\leftarrow
m\theta_k+(1-m)\theta_q,
\qquad
m\approx1
$$

Queue에는 여러 과거 step에서 만들어진 key가 섞인다. Key encoder가 매 step 급격히 바뀌면 old key와 new query가 서로 다른 coordinate system에 놓여 dictionary가 불안정해진다. EMA는 representation space를 천천히 움직여 queue의 일관성을 높인다.

### **7.3 Queue 기반 negative dictionary**

현재 minibatch의 positive key는 loss 계산 뒤 queue에 enqueue하고 가장 오래된 key는 dequeue한다. Queued key는 이미 계산된 tensor이므로 gradient를 받지 않는다.

MoCo의 핵심은 `queue` 하나가 아니라 다음 결합이다.

- 작은 current batch
- 큰 FIFO negative dictionary
- No-gradient key branch
- Slowly moving momentum encoder

MoCo v2는 여기에 SimCLR의 stronger augmentation과 nonlinear projection head를 결합해 baseline을 개선했다.

## **8. CPC의 sequence-level prediction**

Instance contrastive learning이 같은 image의 두 view를 묶는다면 Contrastive Predictive Coding(CPC)은 과거 context와 실제 future latent를 묶는다.

![Instance contrast와 sequence contrast의 차이에서 autoregressive context·future latent prediction·audio와 visual CPC로 이어지는 구조]({{ '/assets/img/posts/cs231n-lecture-12/animations/contrastive-predictive-coding.gif' | relative_url }})

### **8.1 Autoregressive context와 future latent**

Encoder는 sequence의 각 input을 latent로 바꾼다.

$$
z_t=g_{\text{enc}}(x_t)
$$

[RNN의 hidden state](/posts/cs231n-lecture-7/#2-rnn의-hidden-state와-시간축-parameter-sharing)처럼 autoregressive model은 현재까지의 latent를 context $c_t$로 요약한다.

$$
c_t=g_{\text{ar}}(z_{\le t})
$$

Raw future pixel이나 waveform을 그대로 복원하는 대신 $c_t$가 실제 future latent $z_{t+k}$를 negative candidate 중에서 식별하게 만든다. 고주파 detail 전체보다 미래까지 유지되는 구조를 representation에 남기려는 설계다.

### **8.2 Time-dependent score와 InfoNCE**

Prediction horizon $k$마다 trainable matrix $W_k$를 두면 score는

$$
s_k(z_{t+k},c_t)
=
z_{t+k}^{\top}W_kc_t
$$

$z_{t+k}\in\mathbb R^{d_z}$, $c_t\in\mathbb R^{d_c}$, $W_k\in\mathbb R^{d_z\times d_c}$이므로 각 candidate의 score는 scalar가 된다. Positive는 같은 sequence의 실제 $t+k$ latent이고, negative는 다른 sequence나 다른 위치에서 가져온 candidate다. Audio에서는 speaker·phoneme structure, image에서는 위쪽 patch context에서 아래쪽 latent structure처럼 modality에 맞는 predictable information을 학습한다.

## **9. DINO의 negative-free self-distillation**

DINO는 explicit negative pair 없이 서로 다른 view의 output distribution을 맞추는 self-distillation이다.

### **9.1 Student·teacher와 stop-gradient**

Student와 teacher는 같은 architecture를 사용하지만 parameter update 경로가 다르다. Student probability와 centered teacher probability는

$$
p_s(x)
=
\operatorname{softmax}
\left(
\frac{g_{\theta_s}(x)}{\tau_s}
\right)
$$

$$
p_t(x)
=
\operatorname{softmax}
\left(
\frac{g_{\theta_t}(x)-c}{\tau_t}
\right)
$$

$p_s,p_t\in\mathbb R^{B\times K}$이며 여기서 $K$는 semantic class 수가 아니라 self-distillation head의 output dimension이다. 두 global crop $x_a$, $x_b$에 대한 대칭 loss는

$$
\mathcal L_{\text{DINO}}
=
\frac{1}{2}
\left[
H\!\left(p_t(x_a),p_s(x_b)\right)
+
H\!\left(p_t(x_b),p_s(x_a)\right)
\right],
\qquad
H(a,b)=-\sum_j a_j\log b_j
$$

로 쓸 수 있다. 추가 local crop은 student에만 입력되고 global teacher target과 맞춘다.

![DINO student-teacher distribution matching·EMA·centering·stop-gradient에서 DINOv2의 PCA feature correspondence로 이어지는 self-distillation]({{ '/assets/img/posts/cs231n-lecture-12/animations/dino-self-distillation.gif' | relative_url }})

Teacher branch는 stop-gradient이고 parameter는 student의 EMA로 갱신된다.

$$
\theta_t
\leftarrow
m\theta_t+(1-m)\theta_s
$$

Student는 global crop과 local crop을 포함한 여러 view를 보고, teacher는 global crop만 본다. Local view가 global teacher target을 맞추려면 부분에서 전체 object semantics를 추론해야 한다.

### **9.2 Centering·sharpening 기반 collapse 방지**

Negative가 없으면 모든 input에 같은 output을 내는 collapse가 가능하다. DINO는 teacher output의 centering과 낮은 teacher temperature를 이용한 sharpening을 함께 사용한다.

- Centering은 특정 dimension이 모든 sample에서 지배하는 현상을 누른다.
- Sharpening은 teacher target이 완전히 uniform해지는 현상을 막는다.
- EMA teacher는 student보다 천천히 움직이는 target을 만든다.

Centering과 sharpening은 서로 반대 방향의 collapse를 제어하므로 하나만 떼어 설명하기보다 균형으로 보는 편이 정확하다.

### **9.3 DINO와 DINOv2의 emergent object structure**

DINO로 학습한 ViT의 attention에는 object region과 part structure가 label 없이 나타날 수 있다. 이는 representation의 spatial coherence를 보여 주지만 segmentation mask 자체는 아니다.

DINOv2의 patch feature를 여러 image에 걸쳐 PCA한 결과에서는 pose, style, instance가 달라도 bird의 wing이나 vehicle body처럼 비슷한 part가 유사한 component로 대응한다. 이는 DINOv2가 대규모 curated data와 안정화된 self-supervised training으로 만든 dense feature의 성질이다. DINO의 teacher-student objective와 DINOv2 전체 training recipe를 같은 방법으로 단순화할 수는 없다.

## **10. Reconstruction·contrastive·distillation의 비교**

세 계열의 차이는 architecture 이름보다 **무엇을 target으로 삼는지**에서 가장 선명하게 드러난다.

| 방법 | Target·positive 구성 | Negative | 학습 후 핵심 module | 주요 병목 |
|---|---|---|---|---|
| MAE | 가려진 patch의 pixel | 없음 | Encoder | Mask와 reconstruction target 설계 |
| SimCLR | 같은 image의 두 augmentation | In-batch view | Projection 전 encoder | 큰 batch와 augmentation 선택 |
| MoCo | Query와 matching key | FIFO queue | Query encoder | Queue key의 consistency |
| CPC | Context와 실제 future latent | 다른 sample·time candidate | Encoder와 context model | Candidate 구성과 sequence modeling |
| DINO | Teacher의 다른-view distribution | 없음 | EMA teacher encoder | Collapse 방지와 teacher lag |

Reconstruction은 입력의 내용을 보존하는 데 강하지만 pixel detail에 과도하게 집중할 수 있다. Contrastive learning은 augmentation으로 정한 identity와 invariance를 직접 학습하지만 false negative와 candidate 규모에 민감하다. Self-distillation은 explicit negative를 없애지만 stable teacher와 collapse 방지가 핵심이 된다.

현대 self-supervised system은 masked prediction, teacher target, contrastive objective와 clustering을 함께 사용하기도 한다. 각 loss가 representation에서 **보존할 정보와 버릴 정보**를 어떻게 정의하는지가 조합의 기준이다.

## **11. PyTorch 기반 self-supervised objective 검산**

### **11.1 NT-Xent affinity matrix와 positive index**

아래 코드는 `[view1 전체, view2 전체]` 순서로 쌓은 embedding에서 SimCLR loss를 계산한다. 이 ordering에서는 sample $i$의 positive index가 $i+N$ 또는 $i-N$이다.

```python
import torch
import torch.nn.functional as F


def nt_xent(z1: torch.Tensor, z2: torch.Tensor, tau: float = 0.2):
    """z1, z2: 같은 N개 image에서 만든 두 view, shape [N, D]."""
    if z1.shape != z2.shape:
        raise ValueError("two views must have the same shape")

    n = z1.size(0)
    z = F.normalize(torch.cat([z1, z2], dim=0), dim=1)  # [2N, D]
    logits = z @ z.T / tau                              # [2N, 2N]

    self_mask = torch.eye(2 * n, dtype=torch.bool, device=z.device)
    logits = logits.masked_fill(self_mask, float("-inf"))

    index = torch.arange(2 * n, device=z.device)
    target = (index + n) % (2 * n)
    loss = F.cross_entropy(logits, target)
    return loss, logits, target


z1 = torch.randn(4, 32, requires_grad=True)
z2 = torch.randn(4, 32, requires_grad=True)
loss, affinity, target = nt_xent(z1, z2)
loss.backward()

print(affinity.shape)  # torch.Size([8, 8])
print(target.tolist()) # [4, 5, 6, 7, 0, 1, 2, 3]
```

같은 instance의 두 view를 `[x_0^a,x_0^b,x_1^a,x_1^b,\ldots]`처럼 인접하게 쌓았다면 target 계산이 달라진다. Pair ordering을 확인하지 않고 `index ^ 1`이나 `index + N`을 복사하면 다른 sample을 positive로 지정하는 조용한 bug가 생긴다.

### **11.2 Momentum encoder와 gradient 차단**

MoCo의 key encoder는 query encoder의 gradient를 공유하지 않는다. Parameter 복사와 EMA update는 gradient graph 밖에서 수행한다.

```python
import copy
import torch
from torch import nn


query_encoder = nn.Linear(16, 8)
key_encoder = copy.deepcopy(query_encoder)

for parameter in key_encoder.parameters():
    parameter.requires_grad_(False)


@torch.no_grad()
def momentum_update(query: nn.Module, key: nn.Module, momentum: float):
    for param_q, param_k in zip(query.parameters(), key.parameters()):
        param_k.mul_(momentum).add_(param_q, alpha=1.0 - momentum)


x = torch.randn(4, 16)
q = query_encoder(x)
k = key_encoder(x)
loss = -(q * k.detach()).sum(dim=1).mean()
loss.backward()

assert query_encoder.weight.grad is not None
assert key_encoder.weight.grad is None
momentum_update(query_encoder, key_encoder, momentum=0.999)
```

`k.detach()`와 `requires_grad_(False)`는 key branch의 gradient 차단을 드러내고, 실제 key parameter 변화는 `momentum_update`에서만 일어난다. Queue에 넣는 key도 detached tensor여야 이전 step의 graph를 붙잡지 않는다.

### **11.3 Masked-patch reconstruction loss**

MAE loss는 patch별 MSE를 먼저 만든 뒤 masked position만 평균한다.

```python
import torch


def masked_patch_mse(
    prediction: torch.Tensor,
    target: torch.Tensor,
    mask: torch.Tensor,
) -> torch.Tensor:
    """
    prediction, target: [B, N, patch_dim]
    mask: [B, N], masked patch가 1
    """
    patch_loss = (prediction - target).pow(2).mean(dim=-1)  # [B, N]
    masked_count = mask.sum().clamp_min(1)
    return (patch_loss * mask).sum() / masked_count


prediction = torch.randn(2, 16, 48, requires_grad=True)
target = torch.randn_like(prediction)
mask = torch.zeros(2, 16)
mask[:, :12] = 1  # 75% masking

loss = masked_patch_mse(prediction, target, mask)
loss.backward()

assert prediction.grad[:, 12:].abs().sum() == 0
```

마지막 assertion은 visible patch가 loss에 직접 기여하지 않는다는 점을 확인한다. Encoder가 visible patch를 처리한다는 사실과 loss가 masked patch에만 걸린다는 사실은 서로 다른 설계 요소다.

## **12. 정리**

자기지도 학습은 label을 없애는 한 가지 trick이 아니라, data 안에서 target과 positive relation을 설계하는 representation-learning framework다.

- Pretext task는 자동 target을 제공하지만 downstream representation으로 평가해야 한다.
- Rotation과 jigsaw는 orientation·part configuration을, inpainting과 colorization은 context·semantics를 요구한다.
- Video colorization의 feature affinity는 color propagation을 넘어 mask와 keypoint tracking에 재사용된다.
- MAE는 75% masking, visible-only encoder, lightweight decoder, masked-only loss의 비대칭 구조다.
- InfoNCE는 positive index를 맞히는 candidate classification이며 temperature가 logit scale을 조절한다.
- SimCLR은 augmentation으로 invariance를 정의하고 projection head로 $h$와 $z$의 역할을 나눈다.
- MoCo는 queue의 규모와 EMA key encoder의 consistency를 함께 설계한다.
- CPC는 future latent의 predictability를, DINO는 EMA teacher의 cross-view distribution을 학습 신호로 사용한다.

결국 method를 구분하는 가장 좋은 질문은 “negative가 있는가” 하나가 아니다. **어떤 두 관측을 같은 대상으로 묶고, 어떤 정보를 복원하거나 예측하며, 학습이 끝난 뒤 어느 representation을 downstream에 남기는가**가 핵심이다.
