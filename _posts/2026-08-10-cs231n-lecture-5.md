## **0. 이 글의 목표**

[Lecture 4의 신경망과 역전파](/posts/cs231n-lecture-4/)까지 오면 이미지를 분류하는 신경망을 학습시킬 도구는 거의 갖춘 셈이다. tensor를 computational graph에 넣고, scalar loss를 만든 뒤, backpropagation으로 gradient를 구해 parameter를 갱신하면 된다.

남은 문제는 **이미지를 어떤 연산으로 처리할 것인가**다. 이미지는 단순히 숫자 $D$개가 모인 vector가 아니라 높이, 너비, channel을 가진 공간적 신호다. 이 구조를 무시하고 모든 pixel을 펼치면 서로 이웃한 pixel이라는 정보와 같은 모양이 다른 위치에 나타날 수 있다는 성질을 모델에 직접 알려 주지 못한다.

- 이미지를 vector로 펼치면 어떤 구조를 잃는가?
- 작은 filter 하나로 어떻게 이미지 전체를 탐색할 수 있는가?
- filter 하나와 activation map 하나는 어떻게 연결되는가?
- padding과 stride는 출력 크기와 receptive field를 어떻게 바꾸는가?
- convolution은 물체의 이동에 대해 invariant한가, equivariant한가?

전체 계산은 다음 흐름으로 이어진다.

$$
\begin{aligned}
\text{pixels}
&\longrightarrow \text{local template matching} \\
&\longrightarrow \text{feature maps} \\
&\longrightarrow \text{spatial downsampling} \\
&\longrightarrow \text{class scores}
\end{aligned}
$$

**CNN은 이미지의 2차원 구조를 유지한 채 같은 local detector를 모든 위치에 공유하고, 그 detector 자체를 데이터로부터 학습하는 신경망이다.**

## **1. Hand-crafted feature에서 learned feature로**

### **1.1 Pixel을 그대로 비교하는 대신 표현을 설계했다**

[Lecture 2의 pixel 기반 분류](/posts/cs231n-lecture-2/)에서 확인했듯이 raw pixel은 의미와 직접 대응하지 않는다. 물체가 몇 pixel만 이동하거나 조명이 달라져도 입력 vector는 크게 변한다. 과거의 computer vision system은 이 간극을 줄이기 위해 사람이 image feature를 설계했다.

- **Color histogram**은 각 색이 얼마나 등장하는지를 센다. 위치가 달라져도 비슷한 색 분포를 얻지만, 어느 색이 어디에 있었는지는 버린다.
- **Histogram of Oriented Gradients, HOG**는 작은 영역마다 edge 방향을 센다. 색에는 비교적 둔감하고 local shape에는 민감하다.
- **Bag of Visual Words**는 image patch를 미리 만든 visual codebook의 단어에 대응시킨 뒤 등장 빈도로 이미지를 표현한다.

각 feature는 일부 변화에는 강하지만 다른 정보를 포기한다. Color histogram은 공간 구조를 버리고, HOG는 색보다 edge에 집중한다. 그래서 하나의 완벽한 feature를 찾기보다 여러 feature vector를 이어 붙여 classifier에 넣는 방식이 흔했다.

![raw pixel에서 color histogram, HOG, Bag of Visual Words를 거쳐 hand-crafted feature와 end-to-end ConvNet을 비교하는 과정]({{ '/assets/img/posts/cs231n-lecture-5/animations/handcrafted-to-learned-features.gif' | relative_url }})

이 구조에서는 사람이 feature extractor $\phi$를 먼저 정하고, 학습은 그 뒤의 classifier에 집중된다.

$$
x
\xrightarrow{\text{hand-crafted }\phi}
\phi(x)
\xrightarrow{W}
s
$$

feature가 버린 정보는 classifier가 복구할 수 없다. 예를 들어 $\phi$가 위치를 완전히 제거했다면 그 뒤의 선형층은 원래 pixel의 배치를 다시 알아낼 방법이 없다. **표현을 어떻게 설계했는지가 학습 가능한 함수의 상한을 미리 정하는 셈이다.**

### **1.2 End-to-end learning은 설계 대상을 바꾼다**

ConvNet도 입력 image를 class score로 바꾸는 함수라는 점은 같다. 차이는 feature extractor의 weight까지 loss의 gradient를 받아 함께 바뀐다는 데 있다.

$$
x
\xrightarrow{\phi_{\theta}}
\phi_{\theta}(x)
\xrightarrow{W}
s
\xrightarrow{}
L
$$

$$
\theta\leftarrow\theta-\eta\frac{\partial L}{\partial\theta},
\qquad
W\leftarrow W-\eta\frac{\partial L}{\partial W}
$$

사람이 edge의 각도나 color bin을 하나씩 코딩하는 대신, 데이터와 [gradient 기반 최적화](/posts/cs231n-lecture-3/)가 task에 필요한 filter 값을 찾는다. 이때 **end-to-end가 인간의 설계를 없애는 것은 아니다.** 사람이 정하는 대상이 구체적인 feature에서 layer의 순서, channel 수, kernel 크기, stride 같은 architecture로 이동한다.

![이미지를 펼치는 MLP에서 공간 구조를 보존하는 convolution과 pooling, end-to-end 학습으로 전환하는 과정]({{ '/assets/img/posts/cs231n-lecture-5/animations/flatten-to-convnet.gif' | relative_url }})

1998년 LeNet은 문서 인식에 convolution과 gradient-based learning을 적용했고, 2012년 AlexNet은 GPU와 대규모 데이터로 같은 핵심 아이디어를 크게 확장했다. 이후 CNN은 classification, detection, segmentation, captioning, image generation으로 퍼졌다. 지금은 Vision Transformer와 convolution-attention hybrid도 널리 쓰이지만, locality, weight sharing, spatial hierarchy를 연산에 넣는 방법을 이해하려면 CNN이 가장 직접적인 출발점이다.

## **2. Fully connected layer가 이미지와 잘 맞지 않는 이유**

### **2.1 Fully connected layer는 입력 전체와 template을 비교한다**

$32\times32\times3$ image를 펼치면 길이 3072의 vector가 된다. class가 10개인 선형 분류기는 다음 계산을 수행한다.

$$
\begin{aligned}
x&\in\mathbb R^{3072},
&W&\in\mathbb R^{10\times3072} \\
s&=Wx+b
\end{aligned}
$$

$W$의 각 row는 입력 전체와 같은 크기의 template이다. 한 class score는 그 template과 전체 image의 dot product다.

$$
s_c=w_c^\top x+b_c
$$

두 vector가 같은 방향으로 정렬되고 크기도 클수록 dot product가 커지므로 이를 template과 입력의 일치 점수로 볼 수 있다. 문제는 template이 **전체 image의 절대 위치**에 묶인다는 점이다. 왼쪽 위에서 배운 edge와 오른쪽 아래의 같은 edge를 별개의 pattern으로 취급한다.

### **2.2 Flatten은 값이 아니라 이웃 관계를 지운다**

flatten 자체가 pixel 값을 없애는 것은 아니다. $32\times32\times3$의 모든 값은 길이 3072 vector 안에 그대로 있다. 사라지는 것은 layer가 이용할 수 있는 명시적인 공간 구조다.

- 어느 두 pixel이 가로·세로로 이웃하는가?
- 같은 local pattern이 다른 위치에도 나타났는가?
- 위쪽의 feature와 아래쪽의 feature가 어떤 배치를 이루는가?

MLP도 충분한 데이터와 parameter가 있다면 이런 규칙을 학습할 수 있다. 다만 모델이 처음부터 그 성질을 알고 있지 않으므로 위치마다 비슷한 detector를 반복해서 배워야 한다. CNN은 다음 두 가정을 연산 구조에 넣는다.

1. **Local connectivity**: 가까운 pixel의 조합이 먼저 의미 있는 local pattern을 만든다.
2. **Weight sharing**: 같은 pattern detector는 image의 어느 위치에서도 재사용할 수 있다.

이처럼 모델이 문제에 대해 미리 갖는 구조적 가정을 **inductive bias**라고 한다. CNN의 장점은 단순히 parameter 수가 적다는 데서 끝나지 않는다. image에서 유용한 함수가 어떤 모양일 가능성이 높은지를 학습 전에 제한해 더 적은 데이터로도 그 함수를 찾기 쉽게 만든다.

## **3. Convolution layer는 무엇을 계산하는가?**

### **3.1 작은 filter로 local dot product를 계산한다**

입력이 $C_{\mathrm{in}}\times H\times W$이고 kernel 크기가 $K_h\times K_w$라고 하자. filter 하나의 shape은 다음과 같다.

$$
C_{\mathrm{in}}\times K_h\times K_w
$$

filter는 공간적으로는 작지만 **channel 방향으로는 입력 전체를 관통한다.** RGB image에 $5\times5$ convolution을 적용한다면 filter는 $3\times5\times5$다. 한 위치의 input patch도 같은 shape이고, 두 tensor를 펼쳐 dot product한 값 하나가 output activation 하나가 된다.

![fully connected layer의 전역 template에서 channel 전체를 관통하는 작은 convolution filter의 local dot product로 바뀌는 과정]({{ '/assets/img/posts/cs231n-lecture-5/animations/local-template-matching.gif' | relative_url }})

stride와 padding을 포함하면 한 위치의 계산은 다음처럼 쓸 수 있다.

$$
\begin{aligned}
Y_{n,o,i,j}
&=
b_o
+
\sum_{c=0}^{C_{\mathrm{in}}-1}
\sum_{u=0}^{K_h-1}
\sum_{v=0}^{K_w-1} \\
&\qquad
W_{o,c,u,v}
X_{n,c,\,iS_h+u-P_h,\,jS_w+v-P_w}
\end{aligned}
$$

$n$은 batch index, $o$는 output channel, $(i,j)$는 output의 공간 위치다. 식은 복잡해 보이지만 핵심은 단순하다.

1. output 위치 $(i,j)$가 볼 input patch를 고른다.
2. 그 patch와 filter $W_o$의 원소별 곱을 모두 더한다.
3. output channel $o$의 bias $b_o$를 더한다.

Deep-learning library의 `Conv2d`는 보통 kernel을 뒤집지 않고 위 식을 계산한다. 신호처리의 엄밀한 명칭으로는 cross-correlation이지만, filter를 학습하는 신경망에서는 관례적으로 convolution이라고 부른다.

### **3.2 Filter 하나가 activation map 하나를 만든다**

같은 filter를 image의 모든 위치에 놓아 보면 위치마다 scalar response가 나온다. 이 response를 원래 위치에 맞춰 배열한 2차원 평면이 **activation map** 또는 **feature map**이다.

![한 filter를 모든 공간 위치에 공유해 activation map을 만들고 여러 filter의 map을 output channel로 쌓는 과정]({{ '/assets/img/posts/cs231n-lecture-5/animations/convolution-activation-maps.gif' | relative_url }})

filter가 어떤 diagonal edge와 비슷한 pattern을 학습했다면 activation map의 큰 값은 그 edge가 나타난 위치를 가리킨다. 여기서 구분해야 할 것은 다음 둘이다.

- **Filter**: 학습되는 작은 weight tensor다.
- **Activation map**: 현재 입력에 filter를 적용해 얻은 공간별 response다.

filter 값은 여러 image와 위치에 공유되지만 activation map은 입력마다 달라진다. filter가 6개면 서로 다른 template matching을 6번 수행하고, activation map 6개를 channel 방향으로 쌓는다. 따라서 **output channel 수는 filter 수와 같다.**

### **3.3 Batch까지 포함하면 모든 tensor가 4차원이다**

PyTorch가 주로 사용하는 NCHW 표기에서 shape은 다음과 같다.

$$
X:
N\times C_{\mathrm{in}}\times H\times W
$$

$$
W:
C_{\mathrm{out}}\times C_{\mathrm{in}}\times K_h\times K_w
$$

$$
b:
C_{\mathrm{out}}
$$

$$
Y:
N\times C_{\mathrm{out}}\times H_{\mathrm{out}}\times W_{\mathrm{out}}
$$

![여러 filter와 bias에서 공간별 feature vector를 만들고 batch input과 일반적인 convolution tensor shape로 확장하는 과정]({{ '/assets/img/posts/cs231n-lecture-5/animations/convolution-batch-shapes.gif' | relative_url }})

Kernel의 두 공간 축은 자료에 따라 $K_w\times K_h$ 또는 $K_h\times K_w$ 순서로 적기도 한다. 이 글은 PyTorch tuple 순서인 $(K_h,K_w)$로 통일하며, non-square kernel에서는 framework의 인자 순서를 확인해야 한다.

bias는 공간 위치마다 따로 두지 않는다. output channel 하나에 scalar 하나를 두고 그 channel의 모든 $(i,j)$에 broadcast한다. Kernel weight와 마찬가지로 bias도 공간 위치에 공유되는 셈이다.

### **3.4 학습되는 값과 사람이 정하는 값**

Convolution을 처음 보면 “filter는 누가 만드는가?”와 “kernel 크기는 누가 정하는가?”가 섞이기 쉽다.

- **Hyperparameter**: $C_{\mathrm{out}}$, $K_h$, $K_w$, stride, padding처럼 학습 전에 정해 tensor shape와 계산 그래프를 결정한다.
- **Parameter**: filter tensor 내부의 모든 scalar와 bias다. 무작위로 초기화한 뒤 loss gradient로 갱신한다.

기본 convolution layer 안에서는 모든 filter의 kernel 크기를 같게 두어 하나의 dense tensor로 계산한다. 서로 다른 크기의 kernel을 동시에 쓰고 싶다면 Inception처럼 여러 convolution branch를 병렬로 만들고 그 출력을 합치는 방식으로 더 큰 계산 그래프를 구성할 수 있다.

학습 loop는 새로운 특별한 절차가 아니다.

$$
\begin{aligned}
\text{batch}
&\rightarrow \text{forward}
\rightarrow \text{loss} \\
&\rightarrow \text{backward}
\rightarrow \text{optimizer step}
\end{aligned}
$$

매 optimizer step에서 $\partial L/\partial W$가 filter 값을 바꾼다. 반면 filter 수와 kernel 크기는 tensor shape 자체를 바꾸므로 일반적인 gradient descent의 대상이 아니다.

## **4. Convolution을 쌓을 때 비선형성이 필요한 이유**

Bias를 제외한 convolution은 input의 weighted sum을 만드는 선형 연산이다. 두 convolution operator를 $A_1,A_2$라고 하면 activation 없이 연달아 적용한 합성도 선형이다.

$$
Y=A_2(A_1(X))=A_{\mathrm{eff}}(X)
$$

Bias까지 포함하면 affine operator의 합성이 된다. 어느 쪽이든 layer를 늘려도 표현 가능한 함수의 종류가 본질적으로 늘지 않는다. 그래서 convolution 사이에 ReLU 같은 nonlinearity를 넣는다.

![convolution layer 사이에 ReLU activation을 넣어 ConvNet block을 구성하는 과정]({{ '/assets/img/posts/cs231n-lecture-5/animations/conv-relu-stack.gif' | relative_url }})

전형적인 block은 다음과 같다.

$$
X_{l+1}
=
\operatorname{ReLU}(\operatorname{Conv}(X_l;W_l,b_l))
$$

이 구조는 Lecture 4의 MLP와 같은 원리다. 달라진 것은 affine layer가 모든 입력과 연결되는 matrix multiplication에서 local connectivity와 weight sharing을 갖는 convolution으로 바뀌었다는 점이다.

### **4.1 학습된 filter는 깊이에 따라 보는 구조가 달라진다**

첫 layer의 filter는 RGB 값에 직접 작용하므로 작은 image patch처럼 시각화할 수 있다. 학습이 끝난 뒤에는 대체로 다음 pattern이 자주 나타난다.

- horizontal, vertical, diagonal edge
- 밝고 어두운 blob
- red-green처럼 대비되는 color pattern

깊은 layer의 filter는 RGB가 아니라 앞 layer가 만든 feature map을 입력으로 받는다. filter 자체를 그대로 그림으로 보기 어렵고, 그 filter가 강하게 반응하는 input patch를 모아 의미를 추정한다. 그 결과 눈, 글자 조각, 원형 구조처럼 더 넓은 pattern에 반응하는 경우가 나타난다.

![전체 image template에서 첫 convolution layer의 edge와 color filter, 깊은 layer의 더 큰 구조로 이어지는 과정]({{ '/assets/img/posts/cs231n-lecture-5/animations/learned-filter-hierarchy.gif' | relative_url }})

이 현상을 단순히 “깊은 층이라서 자동으로 추상적이 된다”고 외우면 원인을 놓친다. convolution을 쌓을수록 뒤쪽 activation 하나에 영향을 줄 수 있는 원본 image 영역, 즉 receptive field가 넓어지기 때문에 더 큰 구조를 조합할 수 있다.

또한 모든 filter를 같은 값으로 초기화하면 같은 input과 loss에서 같은 gradient를 받아 계속 같은 filter로 남는다. 서로 다른 random initialization이 filter 사이의 대칭을 깨뜨리므로 각 filter가 다른 feature로 분화할 수 있다.

## **5. Output size, padding, stride**

### **5.1 Output size 공식**

각 공간 축은 독립적으로 계산한다. dilation이 1일 때 output 크기는 다음과 같다.

$$
H_{\mathrm{out}}
=
\left\lfloor
\frac{H+2P_h-K_h}{S_h}
\right\rfloor+1
$$

$$
W_{\mathrm{out}}
=
\left\lfloor
\frac{W+2P_w-K_w}{S_w}
\right\rfloor+1
$$

$7\times7$ input에 $3\times3$ filter를 padding 없이 한 칸씩 움직이면 filter의 왼쪽 위 모서리를 놓을 수 있는 위치가 각 축에 5개다.

$$
\frac{7-3}{1}+1=5
$$

따라서 output은 $5\times5$가 된다.

![7×7 input 위에서 3×3 filter가 이동해 5×5 output을 만들고 padding으로 크기를 보존하는 전체 과정]({{ '/assets/img/posts/cs231n-lecture-5/animations/padding-output-size.gif' | relative_url }})

분자 부분이 stride로 정확히 나누어지지 않으면 마지막 kernel 위치가 input에 맞지 않는다. framework는 보통 floor에 해당하는 위치까지만 사용하지만, architecture를 설계할 때는 의도한 output shape이 나오는지 직접 확인해야 한다.

### **5.2 Padding은 공간 크기를 유지한다**

padding이 없으면 convolution을 지날 때마다 feature map이 줄어든다. stride 1이고 홀수 kernel을 사용할 때

$$
P=\frac{K-1}{2}
$$

로 두면 input과 output의 공간 크기가 같다.

$$
W_{\mathrm{out}}
=
W-K+1+2P
=W
$$

$3\times3$ kernel에는 padding 1, $5\times5$ kernel에는 padding 2를 두는 식이다. 이 설정은 residual connection처럼 두 feature map의 shape을 맞춰야 할 때도 편리하다.

다만 zero padding은 image 밖의 값이 0이라고 가정한다. 실제 image 경계에 없던 강한 대비가 생길 수 있고, 중앙과 경계가 서로 다른 문맥을 보게 된다. **공간 크기를 유지하는 편리한 선택이지 경계 정보를 완벽하게 보존하는 연산은 아니다.**

### **5.3 Stride는 위치를 건너뛰며 downsampling한다**

stride $S=2$는 filter를 두 칸씩 이동시킨다. $7\times7$ input, $3\times3$ kernel, padding 0이라면

$$
W_{\mathrm{out}}
=
\frac{7-3}{2}+1
=3
$$

이므로 output은 $3\times3$다.

![7×7 input에서 3×3 filter가 두 칸씩 이동하며 3×3 output을 만드는 strided convolution]({{ '/assets/img/posts/cs231n-lecture-5/animations/strided-convolution.gif' | relative_url }})

stride는 단지 output shape을 맞추는 옵션이 아니다.

- feature map의 높이와 너비를 줄인다.
- 뒤 layer의 activation 하나가 원본 image에서 담당하는 간격을 넓힌다.
- activation memory와 뒤 layer의 연산량을 줄인다.
- 일부 위치를 건너뛰므로 작은 이동에 대한 정보가 손실되거나 aliasing이 생길 수 있다.

따라서 stride는 계산량, spatial resolution, receptive field가 함께 바뀌는 architecture 선택이다.

## **6. Receptive field는 한 activation이 볼 수 있는 원본 범위다**

### **6.1 Local operator를 쌓으면 전역 정보를 모을 수 있다**

첫 $3\times3$ convolution의 activation 하나는 input의 $3\times3$ 영역만 본다. 다음 $3\times3$ convolution은 앞 feature map의 $3\times3$을 보지만, 그 각 원소가 이미 원본의 $3\times3$에 의존한다. 결과적으로 두 번째 layer의 한 activation은 원본의 $5\times5$ 영역에 의존한다.

stride 1, kernel size $K$, convolution $L$개라면 계산 그래프상 receptive field의 한 변 길이는

$$
r_L=1+L(K-1)
$$

이다. $3\times3$ convolution을 세 개 쌓으면 $3\rightarrow5\rightarrow7$로 커진다.

![한 layer의 local receptive field가 convolution을 쌓으면서 원본 image의 더 넓은 영역으로 확장되는 과정]({{ '/assets/img/posts/cs231n-lecture-5/animations/receptive-field.gif' | relative_url }})

여기서 “이전 layer에서 $3\times3$을 본다”와 “원본 input에서 $7\times7$을 본다”를 구분해야 한다. kernel size는 바로 앞 tensor에서 읽는 범위이고, receptive field는 여러 layer를 거슬러 원본에서 영향을 받을 수 있는 범위다.

### **6.2 Stride까지 포함한 일반적인 계산**

layer $l$의 kernel size를 $k_l$, stride를 $s_l$이라고 하자. 원본 input에서 인접한 feature가 떨어진 간격을 jump $j_l$, receptive field를 $r_l$이라 두면 다음 재귀식으로 계산할 수 있다.

$$
j_0=1,\qquad r_0=1
$$

$$
j_l=j_{l-1}s_l
$$

$$
r_l=r_{l-1}+(k_l-1)j_{l-1}
$$

stride 1 convolution만 쌓으면 $j_l=1$이라 receptive field가 깊이에 대해 선형으로 증가한다. 중간에 stride 2를 넣으면 jump가 2배가 되고, 그 뒤의 kernel 한 칸이 원본에서 더 넓은 간격을 덮는다. Downsampling은 큰 image의 전체 문맥을 적은 layer로 모으는 효율적인 방법이다.

예를 들어 다음 세 layer를 생각해 보자.

| layer | kernel | stride | jump $j_l$ | receptive field $r_l$ |
|---|---:|---:|---:|---:|
| input | - | - | 1 | 1 |
| conv 1 | 3 | 1 | 1 | 3 |
| conv 2 | 3 | 2 | 2 | 5 |
| conv 3 | 3 | 1 | 2 | 9 |

세 번째 layer는 바로 앞 tensor의 $3\times3$만 읽지만 원본에서는 $9\times9$ 범위의 영향을 받을 수 있다. 이 계산이 앞에서 본 “깊은 layer가 더 큰 구조에 반응하는 이유”를 공간적으로 설명한다.

## **7. 하나의 예제로 shape, parameter, 연산량을 분리하기**

다음 convolution을 계산해 보자.

$$
X:3\times32\times32
$$

$$
\begin{aligned}
C_{\mathrm{out}}&=10,
&K&=5 \\
S&=1,
&P&=2
\end{aligned}
$$

### **7.1 Output shape**

output channel은 filter 수와 같으므로 10이다. 공간 크기는

$$
\frac{32+2\cdot2-5}{1}+1=32
$$

이므로 output은 다음 shape이다.

$$
Y:10\times32\times32
$$

### **7.2 Learnable parameter 수**

filter 하나에는 $3\times5\times5=75$개의 weight와 bias 하나가 있다. filter가 10개이므로

$$
10(3\cdot5\cdot5+1)=760
$$

개의 learnable parameter가 있다.

### **7.3 Multiply-add 수**

output 원소 수는

$$
10\cdot32\cdot32=10{,}240
$$

이고, 각 원소는 길이 75의 dot product로 만들어진다. 강의와 같이 bias addition을 제외한 multiply-add를 세면

$$
10{,}240\cdot75=768{,}000
$$

이다.

![3×32×32 input과 10개의 5×5 filter에서 output shape, parameter 760개, multiply-add 768000회를 계산하는 과정]({{ '/assets/img/posts/cs231n-lecture-5/animations/convolution-worked-example.gif' | relative_url }})

parameter가 760개뿐인데 연산량은 훨씬 큰 이유는 **같은 filter를 1024개의 공간 위치에 반복해서 사용하기 때문**이다. Parameter 수는 모델이 저장하고 학습하는 값의 수이고, MACs는 한 번의 forward에서 수행하는 multiply-accumulate 횟수다. Multiply와 add를 각각 한 번의 연산으로 세면 768,000 MACs는 약 1.536M FLOPs가 된다. 둘은 함께 증가할 때도 있지만 같은 개념은 아니다.

![convolution의 input, hyperparameter, weight shape, bias shape, output 크기를 한 장에 정리한 표]({{ '/assets/img/posts/cs231n-lecture-5/slides/p94-convolution-summary.png' | relative_url }})

## **8. 1D, 2D, 3D convolution**

Convolution의 차원은 filter가 이동하는 공간 축의 수를 뜻한다.

- **1D convolution**은 sequence의 한 축을 따라 움직인다. audio waveform, sensor signal, token feature sequence 등에 사용할 수 있다.
- **2D convolution**은 image의 높이와 너비를 따라 움직인다. channel 축은 이동 축이 아니라 각 위치의 feature dimension이다.
- **3D convolution**은 높이, 너비, 깊이 또는 시간처럼 세 공간 축을 따라 움직인다. video clip이나 volumetric medical image가 대표적이다.

![2D convolution에서 1D와 3D convolution으로 filter의 이동 차원을 확장하는 과정]({{ '/assets/img/posts/cs231n-lecture-5/animations/convolution-dimensions.gif' | relative_url }})

일반적인 dense convolution에서는 filter가 각 위치의 input channel 전체를 본다. Grouped convolution이나 depthwise convolution은 channel 연결을 나누는 예외다. 차원이 늘어날수록 kernel volume과 output 위치 수가 함께 커질 수 있으므로 memory와 연산량을 shape로 먼저 계산하는 습관이 중요하다.

---

## **9. Pooling은 parameter 없이 공간 크기를 줄인다**

Pooling은 각 channel을 독립적으로 downsampling한다. 입력이 $C\times H\times W$라면 channel 수 $C$는 유지하고 $H,W$만 줄인다.

Padding이 없을 때 각 공간 축의 output 크기는 convolution과 같은 방식으로 계산한다.

$$
\begin{aligned}
H_{\mathrm{out}}
&=
\left\lfloor\frac{H-K_h}{S_h}\right\rfloor+1 \\
W_{\mathrm{out}}
&=
\left\lfloor\frac{W-K_w}{S_w}\right\rfloor+1
\end{aligned}
$$

### **9.1 Max pooling**

$2\times2$ kernel, stride 2의 max pooling은 겹치지 않는 $2\times2$ 영역마다 최댓값 하나를 남긴다.

$$
Y_{c,i,j}
=
\max_{0\le u,v<2}
X_{c,2i+u,2j+v}
$$

예제의 네 영역에서는 각각 $6,8,3,4$가 선택된다. filter weight나 bias가 없으므로 learnable parameter는 0개다.

![channel별 feature map을 줄이고 각 2×2 영역에서 6, 8, 3, 4를 고르는 max pooling 과정]({{ '/assets/img/posts/cs231n-lecture-5/animations/pooling.gif' | relative_url }})

parameter가 없다고 backward가 없는 것은 아니다. Max pooling의 backward는 forward에서 최댓값이었던 위치로만 upstream gradient를 보낸다. Average pooling은 영역의 모든 위치로 gradient를 나누어 보낸다.

### **9.2 Max와 average는 비선형성이 다르다**

- Max pooling은 여러 입력 중 최댓값을 고르므로 nonlinear operator다.
- Average pooling은 입력의 선형 결합이므로 linear operator다.

따라서 convolution과 average pooling만 계속 쌓는다면 별도의 ReLU 같은 nonlinearity가 필요하다. Max pooling은 자체적으로 nonlinearity를 넣지만, architecture에 따라 convolution 뒤의 activation과 함께 사용하기도 한다.

가장 흔한 목적은 높이와 너비를 절반으로 줄이는 것이므로 $2\times2$, stride 2가 자연스럽다. Pooling은 convolution보다 계산이 싸지만, 어떤 정보를 남길지 학습하지 못한다. 같은 downsampling을 strided convolution으로 수행할 수도 있으므로 둘은 목적과 비용이 다른 architecture 선택이다.

높이와 너비를 정확히 절반으로 줄이는 $2\times2$, stride 2 max pooling에는 보통 padding이 필요하지 않다. Padding의 의미는 framework마다 확인해야 한다. PyTorch `MaxPool2d`는 padded 영역을 $-\infty$로 취급하므로 경계의 음수 값보다 padding이 선택되지는 않는다.

## **10. Translation equivariance와 invariance는 다르다**

image를 $\delta$만큼 이동시키는 연산을 $T_\delta$라고 하자. stride 1 convolution은 경계 조건을 무시하면 다음 성질을 갖는다.

$$
\operatorname{Conv}(T_\delta X)
=
T_\delta\operatorname{Conv}(X)
$$

입력을 먼저 옮기고 convolution한 결과와, 먼저 convolution한 feature map을 같은 만큼 옮긴 결과가 같다. 입력의 pattern이 이동하면 output response도 따라 이동한다. 이것이 **translation equivariance**다.

![입력을 이동한 뒤 convolution 또는 pooling을 적용하는 경로와 그 결과를 이동하는 경로를 비교하는 translation equivariance]({{ '/assets/img/posts/cs231n-lecture-5/animations/translation-equivariance.gif' | relative_url }})

그림의 `Conv or Pool`은 경계와 sampling grid를 무시한 이상화된 설명이다. Zero padding이 만든 경계에서는 주변 문맥이 달라지고, stride 2 convolution이나 stride가 있는 pooling은 한 pixel 이동이 sampling grid와 맞지 않을 수 있다. 따라서 실제 유한 image의 CNN이 모든 크기의 translation에 완벽히 equivariant하다고 말하면 안 된다.

반면 invariance는 입력이 이동해도 출력 자체가 같다는 뜻이다.

$$
f(T_\delta X)=f(X)
$$

두 개념을 구분하면 CNN의 역할이 선명해진다.

- convolution body는 feature의 위치를 보존하며 **같이 이동하는 표현**을 만든다.
- global pooling이나 classification head는 위치별 정보를 모아 최종 class score가 이동에 덜 민감하도록 만들 수 있다.

이 성질은 “network 안에서 image를 일부러 이동시킨다”는 절차가 아니다. 같은 filter를 모든 위치에 공유했을 때 절대 좌표가 아니라 local content에 일관되게 반응한다는 구조적 성질이다.

## **11. PyTorch로 shape를 검산하기**

앞의 숫자 예제는 `torch.nn.Conv2d`로 그대로 확인할 수 있다.

```python
import torch
from torch import nn

x = torch.randn(8, 3, 32, 32)  # NCHW

conv = nn.Conv2d(
    in_channels=3,
    out_channels=10,
    kernel_size=5,
    stride=1,
    padding=2,
    bias=True,
)

y = conv(x)

print(y.shape)  # torch.Size([8, 10, 32, 32])
print(sum(p.numel() for p in conv.parameters()))  # 760
```

Pooling을 이어 붙이면 공간 크기만 절반으로 줄어든다.

```python
pool = nn.MaxPool2d(kernel_size=2, stride=2)
z = pool(y)

print(z.shape)  # torch.Size([8, 10, 16, 16])
```

구현할 때는 다음 오류가 자주 발생한다.

- **NCHW와 NHWC 혼동**: PyTorch `Conv2d`의 기본 입력은 `(N, C, H, W)`다.
- **Input channel 불일치**: filter의 $C_{\mathrm{in}}$은 바로 앞 tensor의 channel 수와 같아야 한다.
- **Output size 오판**: kernel, padding, stride를 공식에 넣어 각 축을 따로 계산한다.
- **Parameter와 activation memory 혼동**: weight가 적어도 큰 feature map을 저장하면 memory 사용량이 클 수 있다.
- **Batch shape 불일치**: 한 dense batch의 image는 같은 $H\times W$여야 한다.

실제 데이터의 aspect ratio가 다르면 같은 크기로 resize하거나 batch 안의 최대 크기에 맞춰 padding한다. Aspect-ratio bucketing은 비슷한 모양끼리 묶어 padding 낭비를 줄이는 방법이며, bucket 안에서도 tensor를 쌓기 전에 $H,W$를 맞춰야 한다.

## **12. 정리**

Fully connected layer는 image 전체를 하나의 template과 비교하지만, convolution은 작은 template을 모든 위치에 공유한다. Filter 하나는 activation map 하나를 만들고, 여러 map이 output channel로 쌓인다. Kernel size와 filter 수는 architecture의 hyperparameter이며, filter 내부 값은 loss와 backpropagation으로 학습되는 parameter다.

Padding은 공간 크기를 조절하고 stride와 pooling은 downsampling을 수행한다. Downsampling은 receptive field가 원본에서 차지하는 범위를 빠르게 넓히고, spatial resolution과 뒤 layer의 계산량을 줄인다. Convolution의 핵심 공간 성질은 완전한 translation invariance가 아니라, 입력의 이동을 feature의 이동으로 보존하는 translation equivariance다.

$$
\boxed{
\begin{aligned}
&\text{local connectivity} \\
+{}&\text{weight sharing} \\
+{}&\text{learned filters} \\
= {}&\text{CNN}
\end{aligned}
}
$$

다음 단계는 이 연산들을 실제 architecture로 조합하는 것이다. 몇 개의 convolution을 묶고 어디에서 downsampling할지, channel을 언제 늘릴지에 따라 AlexNet, VGG, ResNet 같은 서로 다른 CNN이 만들어진다.
